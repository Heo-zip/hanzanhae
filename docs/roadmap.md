# MVP 개발 순서

> 계획이며 일정과 완료 약속은 아니다. 1~6단계는 구현했다. 목표는 마신 횟수로 바뀌었고, 텀블러 용량 기록·취소, 생기·성장, 최근 7일 통계, 알림과 카메라 감지까지 연결했다. 남은 일은 7단계의 서명·공증과 실제 업데이트 확인이다.

## 1. 현재 작업 정리와 환경 확인

- 이미 작업 중인 `design/`, 문서와 창 크기 변경을 확인해 보존한다. 기존 작업을 임의로 덮어쓰거나 이동하지 않는다.
- 현재 브랜치·변경 사항을 확인하고 [Git Flow](conventions.md#git-flow)에 맞춰 안전하게 다음 작업을 준비한다.
- 설치, 린트, 타입 검사, 빌드와 개발 실행을 확인한다. 시안에 사용한 이미지·글꼴의 오프라인 사용과 라이선스를 살펴본다.

## 2. 시안 기반 화면과 창

- `design/garden.html`과 `design/dashboard.html`을 기준으로 정원과 오늘·기록·설정 화면의 레이아웃과 연출을 만든다. 작은 정원 창과 대시보드 메뉴를 구현했다. 오늘 목표·물 기록은 로컬 데이터에 연결했으며 성장·생기도 구현했다. 통계도 연결했다.
- Electron에서 대시보드와 작은 정원 창을 열고, 창 숨기기·Dock 재열기·메뉴 막대·위치와 항상 위 표시를 연결한다.
- 작은 화분, 우클릭 숨기기, 전역 단축키 전환, 메뉴 막대와 Dock 재열기는 연결했다. 이동·위치 저장과 고정 여부 설정도 연결했다.
- Dock보다 아래의 표시 순서를 기본으로 사용한다. 실제 Dock의 확대·자동 숨김 영역에 맞춘 이동은 별도 실험으로 검증하며, 구현 완료로 취급하지 않는다.
- 같은 크기·상태에서 시안과 실제 앱을 비교하고 작은 창이 업무를 방해하지 않는지 확인한다.

## 3. SQLite와 안전한 연결

- 최초 설정 범위에서 Node.js 내장 `node:sqlite`, 스키마 버전 2와 안전한 상태 조회·설정 변경 IPC를 구현했다. 목표 이력과 총량 조정도 저장한다. 물 기록은 버전 3, 취소 이력은 버전 4로 연결했으며 성장 이력과 생기 저장은 버전 5, 정원 창 설정은 버전 7에서 연결했다.

- Electron과 macOS 패키징에 맞는 SQLite 라이브러리를 선택한다. 앱 데이터 폴더, 마이그레이션, 외래 키와 트랜잭션을 구성한다.
- 설정·목표·기록·조정·식물·성장 이력과 중복 요청 처리의 저장 기반을 만든다. 세부 스키마는 [데이터 설계](database.md)를 따른다.
- preload에 필요한 API만 공개하고 입력 검증·오류 처리는 메인에서 수행한다. 네이티브 모듈의 패키징 가능성도 이 단계에서 확인한다.

## 4. 최초 설정과 한 잔 기록

- 최초 설정·한 잔 기록과 재실행 복원을 구현했다.

- 첫 실행 시 목표량과 한 잔 용량을 반드시 입력받고, 설정·초기 식물을 함께 저장한다.
- 물 한 잔 기록, 오늘 총량, 저장 성공 후 연출과 실패 안내를 연결한다. 활성 목표가 없으면 기록을 막는다.
- 앱 재실행 후 데이터 복원, 중복 클릭과 저장 실패를 확인한다.

## 5. 목표 변경과 기록 취소

- 목표 중단 → 새 목표와 오늘 총량 확인·조정 흐름을 만든다. 입력 총량을 기존 기록에 중복해서 더하지 않는다.
- 최근 한 잔과 오늘 현재 목표 기록 전체 취소를 구현했다. 취소 범위·음수 총량 방지와 트랜잭션을 검증했으며 연관 성장도 함께 되돌리도록 연결했다.
- 한국 시간 자정, 요청 중복·재시도와 변경된 화면 상태를 확인한다.

## 6. 성장·생기와 대시보드 통계

- 목표 달성과 초과 기록으로 쌓이는 성장량을 식물 단계에 연결하고, 물 기록에 따른 생기 회복과 종료 중 느린 시듦을 처리한다. 정하지 않은 수치는 임시값임을 명시하고 실제 사용하며 조정한다.
- 최근 7일 그래프·물컵과 평균·최다 섭취일·달성 횟수·연속 달성을 연결한다. 목표가 바뀐 날은 마지막으로 활성화한 목표를 기준으로 한다.
- 목표 없는 날·오늘 진행 중 연속 달성 및 과거 목표 복원은 첫 구현 기준을 정하고 자동 검증했다. [통계 결과](features/water-statistics-REPORT.md)를 따른다.

## 7. 직접 사용과 패키징

- [검증 시나리오](testing.md)에 따라 첫 설정부터 기록·취소·목표 재생성·자정·재실행까지 확인하고, 시안과 실제 화면을 비교한다.
- `.dmg`를 만들어 설치와 재실행, 로컬 데이터 보존을 확인한다. 다른 사람에게 공유할 때 macOS 서명·공증을 별도로 검토한다. 서버 배포는 필요하지 않다.
- Windows(`npm run build:win`, NSIS)와 Linux(`npm run build:linux`, AppImage·deb) 빌드를 추가했다. 기능별 지원 범위는 [운영체제별 지원](features.md#운영체제별-지원)을 따른다. 실제 Windows·Linux에서 설치·실행·투명 정원 창·알림·트레이 확인과 코드 서명, 두 OS의 자동 업데이트는 남았다.

## MVP 이후 제안

- 식물 상태와 마지막 물 기록을 활용한 macOS 시스템 알림을 구현했다. 첫 기준은 [알림 PLAN](features/plant-reminders-PLAN.md)에 있으며 사용자가 표시·클릭을 확인했다. 간격 경과 후 자동 알림은 추가 확인하며 완전 종료 중 알림은 제외한다.
- MediaPipe로 물 마시는 동작(고개 젖힘·빨대)을 감지해 마신 횟수를 자동 기록하고, 대시보드·정원에서 되돌릴 수 있게 구현했다. 오감지 비율과 카메라 사용 중 성능은 사용하며 확인한다.
- 상세 제안과 미정 사항은 [제품 개요](product.md#mvp-이후-아이디어)를 따른다. 각 기능을 시작할 때 별도 PLAN을 작성한다.
