# 검증 시나리오

> 아래 기존 시나리오는 변경 전 기준이다. 현재 횟수·텀블러 분리, 이전 데이터 보존과 UI 검증은 [횟수 목표 결과](features/drink-count-goal-REPORT.md)를 따른다.

> 아래는 구현한 창·최초 설정과 앞으로 구현할 제품 기능의 검증 기준이다. SQLite 저장 기반은 `npm run test:storage`, 정원 좌표 계산은 `npm run test:position`, 알림 조건·서비스는 `npm run test:reminders`, 업데이트 흐름은 `npm run test:update`로 확인한다.

## 변경 후 기본 확인

- 변경 범위에 맞춰 `npm run lint`, `npm run typecheck`, `npm run build`를 실행한다. `build`에는 타입 검사가 포함된다.
- 화면이나 창 동작을 바꾸면 `npm run dev`로 실제 macOS에서 확인한다.
- SQLite나 네이티브 모듈을 추가하면 개발 실행뿐 아니라 macOS 패키징과 재실행도 검증한다.
- 저장·취소처럼 데이터 손실 위험이 있는 동작은 성공뿐 아니라 실패·재시도 경로도 확인한다.

| 기록·성장 저장 도중 오류                                          | 둘 다 확정되지 않고 오류 안내                    |

## 시간·복원·창

- 화분을 눌러 왼쪽 위에 물뿌리개가 잘리지 않고 열리는지, 활성 목표가 없을 때 기록 입력이 비활성화되어 있는지 확인한다.
- 화분을 끌어 옮겨도 물뿌리개가 열리지 않고, 이후 클릭·물주기가 정상인지 확인한다. 위치와 항상 위 여부를 바꾼 뒤 숨기기·복귀·종료·재실행해 복원 여부를 확인한다.
- Dock 위·화면 바닥 선택이 현재 화면에 적용되고 직접 이동 시 선택 강조가 해제되는지 확인한다. 저장 실패나 포인터 취소 시 원래 위치로 복구하는지도 확인한다.
- 화분 우클릭 → 정원 숨기기 후 **⌘ + ⌥ + ⇧ + H**로 다시 열고, 한 번 더 누르면 숨겨지는지 확인한다. 다른 앱에서 입력 중이어도 정원 복귀가 포커스를 가져오지 않는지 확인한다.
- 단축키가 등록되지 않은 경우 메뉴 막대에 실패 안내가 있고 메뉴 막대·Dock으로 다시 열 수 있는지 확인한다.
- 사용자가 정원을 숨긴 뒤 화면 해상도나 Dock 설정을 바꿔도 창이 자동으로 다시 나타나지 않는지 확인한다.
- Dock 확대와 자동 숨김, 전체 화면 앱·여러 작업 공간에서 화분이 Dock과 앱 이름을 가로막지 않는지 실제 macOS에서 확인한다. Dock 움직임을 추적하는 기능은 아직 구현되지 않았다.
- 한국 시간 자정 직전 화면에서 자정 이후 기록·취소를 요청하면 날짜 변경을 알리고 최신 상태를 다시 조회한다.
- 날짜가 바뀌면 오늘 총량은 새 날짜 기준이며 목표는 유지된다. UTC 저장 시각과 한국 날짜 경계를 확인한다.
- 정상 종료 및 강제 종료 뒤 재실행할 때 저장된 기록·설정이 복원되고 종료 중 생기 변화가 설계한 방식으로 반영되는지 확인한다. 구체 속도는 미정이다.
- 창을 숨긴 뒤 메뉴 막대와 Dock에서 각각 다시 열 수 있고, 앱 종료 메뉴는 앱을 완전히 종료하는지 확인한다.
- 모니터 연결이 달라져 저장된 창 위치가 화면 밖일 때 보이는 위치로 복구하는지 확인한다.

## 7일 통계와 성장 단계

- 1,000ml를 달성한 뒤 새 목표를 1,500ml로 바꾸고 총 1,200ml를 마셨다면 그날은 미달성으로 표시한다. 이전 목표의 기록과 성장은 유지한다.
- 과거 날짜의 달성 여부는 현재 목표가 아니라 해당 날짜의 마지막 목표를 기준으로 계산한다. 전날부터 이어진 목표도 확인한다.
- 기섭취량 조정은 총량에 반영하되 오늘 마신 잔 수로 계산하지 않는다.
- 누적 성장량이 단계 기준을 넘으면 해당 식물 외형을 표시하고, 기록 취소로 성장량이 줄어들면 다시 계산한다. 구체적인 수치는 임시 정책을 명시해 검증한다.
- 정원과 대시보드 중 한 창에서 기록·취소·설정을 변경하면 다른 창도 최신 상태를 표시하는지 확인한다.
- 목표 없는 날은 7일 통계 분모에서 제외하고 과거 연속 달성을 끊는다. 오늘 미달성 시 어제부터 연속 달성을 센다. 통계 저장소 테스트에서 이를 검증한다.

## 물 마시기 알림

- 알림을 켜고 간격과 시간대를 저장한 뒤 재실행해 복원되는지 확인한다. 시작·종료가 같거나 허용되지 않은 간격은 저장하지 않는다.
- 목표 없음·목표 달성·시간대 밖에는 보내지 않고, 자정을 넘기는 시간대와 마지막 유효 기록·마지막 알림 간격을 확인한다.
- 테스트 알림은 자동 알림 시각이나 물 기록을 바꾸지 않는다. 자동 알림 실패 시 성공 시각을 저장하지 않고 클릭 시 대시보드를 연다.
- 서명된 macOS 앱에서 알림 허용·거부, 실제 표시와 클릭을 확인한다. 사용자는 표시와 클릭을 확인했고, 임시 경로의 테스트 앱은 거부된 적이 있으므로 [오류 기록](features/plant-reminders-macos-permission-ERROR.md)을 참고한다.
- macOS 개발 앱은 `npm run dev`가 서명한 `한잔해 개발` 앱을 실행한다. 시스템 설정에서 해당 앱의 알림을 허용하고 테스트 알림과 배너를 확인한다. [개발 앱 오류 기록](features/plant-reminders-development-signature-ERROR.md)
- 시작·종료 시간을 시·분 단위로 선택하고 키보드 방향키·Enter·Escape, 저장과 재실행 복원, 시작과 종료가 같을 때 저장 거절을 확인한다.

## 업데이트와 데이터

- 최신 버전 확인·업데이트 연기·다운로드 및 재시작 선택과 네트워크 오류를 확인한다. 연기한 버전의 반복 질문과 중복 요청을 막는다.
- 업데이트 전 저장 확인 실패 시 설치가 시작되지 않아야 한다. 업데이트 종료는 창을 숨기지 않고 닫으며 정상 종료 시 DB를 닫아야 한다.
- 기존 데이터베이스를 새 스키마로 이전하기 전 백업하고, 백업 실패나 더 새로운 스키마를 만났을 때 원본을 변경하지 않아야 한다.
- 실제 Developer ID로 서명된 구버전에서 새 버전으로 업데이트하고 목표·물 기록·성장·설정이 보존되는지 확인한다. 이 실사용 검증은 아직 수행하지 않았다.

## 사용자 경험

- 물 기록이 저장된 뒤 물주기와 식물 반응이 보이고, 실패 시 성공 연출이 나타나지 않는지 확인한다.
- 사용자가 전체 취소 전에 취소·유지되는 범위를 이해할 수 있는지 확인한다.
- 작은 정원이 일이나 공부를 방해하지 않으면서 물 마실 순간을 떠올리게 하는지 실제 사용하며 살펴본다.
