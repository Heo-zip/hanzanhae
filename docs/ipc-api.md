# 내부 API 설계

> 상태: 횟수 목표와 텀블러 기록 분리 작업을 구현하고 검토 중이다. 카메라 감지는 아직 구현하지 않았다.

React는 preload의 허용된 함수만 호출한다. 메인은 앱 화면과 메인 프레임을 확인하고 입력과 날짜·목표를 검증한다. 최초 설정·설정 변경·횟수 기록은 대시보드에서만 허용한다. 정원과 대시보드 모두 텀블러 물 기록을 요청할 수 있다.

| 함수 | 입력과 동작 |
| --- | --- |
| `getState` | 최초 설정 필요, 목표 활성 또는 중단 상태와 오늘 횟수·물 기록·식물 상태를 조회한다. |
| `completeSetup` | 요청 ID, 목표 횟수, 텀블러 용량을 검증하고 최초 설정을 저장한다. |
| `updateSettings` | `cup`, `stop`, `goal` 종류로 텀블러 용량과 목표를 변경한다. 목표 변경은 화면에서 확인한 목표·날짜·총량을 검증한다. |
| `recordDrinkAction` | 요청 ID, 목표 ID, 한국 날짜와 `add` 또는 `undo`를 받는다. 취소는 최신 기록 ID도 확인한다. 횟수만 변경한다. |
| `recordCup` | 요청 ID, 목표 ID와 날짜를 확인한 뒤 저장된 텀블러 용량으로 물·성장·생기를 기록한다. 횟수는 변경하지 않는다. |
| `cancelWater` | `latest` 또는 `today`와 확인한 기록 ID를 받아 물 기록과 관련 성장만 취소한다. 오늘 전체 취소는 현재 목표 범위에 한정된다. |
| `getStatistics` | 날짜별 횟수·목표와 물의 양, 달성·연속 기록 등 최근 통계를 반환한다. 과거 ml 목표는 기존 값으로 유지한다. |
| `getLoginItem`, `setLoginItem` | macOS 로그인 항목 등록 여부를 시스템에서 읽고 바꾼다. DB에 저장하지 않는다. 대시보드 메인 프레임만 호출할 수 있고, 배포 앱(macOS)에서만 바꿀 수 있다. 시스템 허용이 필요하면 `needsApproval`, 반영되지 않으면 실패를 반환한다. |
| `onStateChanged`, `onWaterRecorded` | 상태 갱신과 텀블러 물주기 연출을 다른 창에 알린다. |

요청 ID는 중복 저장을 막는다. 오래된 목표·날짜·취소 대상은 `STALE_STATE`, 검증 오류는 `VALIDATION_ERROR`, 저장 오류는 `STORAGE_ERROR`로 구분한다. 취소는 대상 없음과 조정 후 총량 음수 오류도 구분한다.

정원 위치 설정 조회·변경은 대시보드 메인 프레임에만 허용한다. 드래그 요청은 정원 메인 프레임에서만 허용하고 좌표를 검증한다. 변경 완료 시에만 저장하며 실패하면 이전 창 위치·항상 위 상태로 복구한다.

정원 창은 `setMousePassthrough`로 투명 영역의 클릭 통과를 전환한다. 메인이 통과를 해제하면 `onMouseCaptureReady`로 정원 렌더러에 알려 커서 스타일을 다시 계산한다. 이 알림은 물 기록이나 창 위치를 변경하지 않는다. 실제 macOS에서 커서와 클릭 통과 확인은 남아 있다.

앱 업데이트는 메뉴 막대와 메인 프로세스의 시스템 대화상자에서 처리하며 renderer에 새 IPC를 노출하지 않는다. 재시작을 승인하면 먼저 생기 저장을 확인하고, macOS 업데이트 종료 이벤트에서 창을 실제로 닫는다.

알림 설정은 `getReminderSettings`, `updateReminderSettings`로 조회·저장하고 `testReminder`로 테스트한다. 모두 대시보드 메인 프레임만 호출할 수 있다. 설정은 사용 여부·1~8시간 간격·한국 시간 시작과 종료를 검증하며 `VALIDATION_ERROR` 또는 `STORAGE_ERROR`를 반환한다. 알림을 처음 켰을 때는 확인 알림을 요청하고, 저장 성공과 별도로 표시 성공·실패를 응답에 포함한다. 테스트 알림은 `UNSUPPORTED`·`NOTIFICATION_ERROR`를 추가로 반환하며 발송 간격 기록을 바꾸지 않는다. macOS 개발 앱의 요청 실패는 `DEV_NOTIFICATION_ERROR`, 설정 활성화 시에는 `development-failed`로 구분해 개발 앱의 알림 설정을 안내한다. 이는 오류가 권한 때문이라고 확정하는 코드는 아니다. 사용자가 패키지 앱의 macOS 알림 표시·클릭을 확인했고 간격 경과 후 자동 알림은 추가 확인한다.

## 통신과 데이터 무결성

IPC는 Electron의 화면과 메인 프로세스 사이의 내부 메시지다. HTTP 서버를 사용하지 않으며 원시 IPC나 임의 SQL을 화면에 노출하지 않는다. 쓰기와 요청 중복 방지 결과는 SQLite 트랜잭션으로 묶는다. 기록에 성공한 뒤에만 물주기 연출을 보낸다.

목표 없이 물이나 횟수를 기록할 수 없다. 목표가 바뀌었거나 한국 날짜가 달라진 오래된 요청은 저장하지 않고 최신 상태 확인을 안내한다. 물 기록과 횟수 기록은 서로 독립적이다.
