# 식물 생기와 성장 결과

- 이슈: [#7](https://github.com/Heo-zip/hanzanhae/issues/7) / 계획: [plant-growth-PLAN](plant-growth-PLAN.md)

## 구현

- 물 기록 시 생기를 회복하고, 하루 목표 첫 달성과 초과량에 따른 성장점을 기록과 함께 저장한다. 정원·대시보드·성장 여정에 누적 성장 단계와 생기를 연결했다.
- 취소된 기록의 성장만 유효 합계에서 제외한다. 이전 목표·날짜의 기록과 성장, 목표 및 조정은 보존한다. 기존 사용자의 과거 기록에는 성장 보상을 소급하지 않는다.
- 앱 실행 중 1분마다 생기를 저장한다. 종료 중에는 마지막 저장 시각부터 더 느린 속도로 시들며 재실행 시 반영한다. 취소 시 생기 회복은 유지한다.
- 성장·시듦 수치는 사용자와 사용하며 조정할 임시값이다. 기준과 계산은 [기능 명세](../features.md#식물-반응과-성장)에 기록했다.
- 사용자 요청에 따라 첫 화면의 내용 묶음을 창 중앙으로 정렬하고 `design/`은 로컬에 두고 Git에서 제외했다.

## 검증

- 저장소 테스트 25개: 목표 달성·초과·취소·재달성, 이전 목표·날짜 보존, 성장 저장 실패 롤백, 생기 경과·재실행·마지막 주기 저장, 스키마 1~4 이전을 확인했다.
- 실제 개발 Electron의 두 창에서 어린 잎부터 꽃까지 상태, 성장 여정, 꽃 모달, 전체 취소 후 새싹 복원을 확인했다. 꽃 단계 화면을 확인했다.
- 첫 화면 내용의 중심을 실제 Electron의 1280×800과 1024×700 창에서 확인했다.
- 임시 데이터의 macOS arm64 ad-hoc 패키지에서 성장·생기·최근/전체 취소·재실행과 패키지 서명·이름 검사를 확인했다. 이 패키지 검사는 첫 화면 정렬 변경 전의 빌드 기준이다.
- 타입 검사·린트·빌드 통과. [이전 테스트 모형 오류](plant-growth-test-fixture-ERROR.md)와 [화면 타입 오류](plant-growth-ui-build-ERROR.md)는 해결했다.

## 남은 확인

- 변경된 생기·성장과 첫 화면의 사용자 직접 QA, 임시 수치의 실제 사용 감각을 확인한다.
- Developer ID 서명·공증, DMG 설치와 다른 Mac 칩은 미검증이다.
