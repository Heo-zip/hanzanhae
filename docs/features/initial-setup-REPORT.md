## 구현 결과

- 첫 실행에 사용자가 하루 목표량과 한 잔 용량을 입력하며 설정을 건너뛸 수 없다. 값이 올바르지 않으면 안내하고 저장하지 않는다.
- Electron 메인이 앱 데이터 폴더의 SQLite에 목표·용량·초기 식물과 요청 처리 결과를 함께 저장한다. 저장 실패 시 전체를 취소하고 입력값을 유지한다.
- 재실행 시 저장된 상태를 복원한다. 목표 중단 상태와 처음 실행을 구분하고, 데이터 조회에 실패했을 때 빈 데이터로 취급하지 않는다.
- Renderer는 preload가 허용한 함수만 사용한다. 메인 프로세스에서 발신자와 입력을 검증하며, 같은 요청이 반복돼도 설정이 중복 저장되지 않도록 한다.
- 계획 당시 제외했던 물 기록·취소·성장·통계는 이후 각각 별도 기능으로 구현했다. 현재 상태는 [현재 작업 상태](../CONTEXT.md)를 따른다.

## 주요 파일

| 경로                                    | 역할                                            |
| --------------------------------------- | ----------------------------------------------- |
| `src/main/storage/database.ts`          | SQLite 스키마와 트랜잭션, 최초 설정과 상태 조회 |
| `src/main/storage/ipc.ts`               | 발신자·입력 검증과 저장소 연결                  |
| `src/preload/index.ts`                  | 화면에 필요한 API만 제공                        |
| `src/renderer/src/features/onboarding/` | 최초 설정 입력과 오류 안내                      |
| `src/shared/appState.ts`                | 화면과 메인이 공유하는 상태·요청 타입           |
| `tests/storage.test.mjs`                | 설정·오류·재실행 등을 포함한 저장소 테스트      |

파일과 스키마에는 이후 기능 변경도 포함돼 있다. 현재 구조와 정책은 [데이터 설계](../database.md)와 [내부 API](../ipc-api.md)를 따른다.

## 검증 기록

| 범위               | 확인한 내용과 결과                                                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 저장소 자동 검사   | 당시 `npm run test:storage` 7개 통과. 정상 설정·중복·입력 검증·저장 실패 롤백·재실행 등을 확인했다.                                                                         |
| 개발 Electron      | 임시 데이터로 입력 차단, 저장 실패 시 입력 유지와 재시도, 정원 갱신, 재실행 복원과 DB 열기 실패 안내를 확인했다.                                                            |
| 빌드 검사          | 당시 `npm run lint`, `npm run build` 통과. 빌드는 타입 검사를 포함한다.                                                                                                     |
| macOS arm64 패키지 | 패키지 충돌을 수정한 후 임시 데이터와 로컬 ad-hoc 서명 앱에서 첫 설정, 두 창, 저장 및 재실행 복원을 확인했다. [충돌 기록](initial-setup-packaged-qa-timeout-ERROR.md) 참고. |

개발·패키지 검증은 기존 기록에 근거한다. 최신 코드 전체를 이 문서 작성 시점에 다시 검증했다는 뜻은 아니다.

## 유지보수 메모

- 트랜잭션은 여러 저장을 하나로 묶어 중간 실패 시 전부 되돌린다. 목표·용량·식물이 일부만 저장되지 않도록 유지한다.
- 최초 설정 전·목표 없음·저장소 오류는 서로 다르다. 오류를 처음 실행으로 잘못 판단해 기존 데이터를 덮어쓰지 않는다.
- 패키지의 한글 앱 이름과 보조 앱 이름 정규화가 일치해야 한다. Electron이나 빌드 도구 변경 시 [패키지 검사](initial-setup-packaged-qa-timeout-ERROR.md)를 다시 확인한다.
