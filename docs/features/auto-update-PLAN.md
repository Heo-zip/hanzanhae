# 기능 계획: 자동 업데이트와 데이터 보존

- 상태: 구현·격리 검증 완료, 서명된 실제 버전 간 검증 전 / 2026-11-14
- 이슈: [#29](https://github.com/Heo-zip/hanzanhae/issues/29)
- 기준: Electron·React·SQLite, Mac 우선, 로그인 없이 앱 사용

## 목적과 범위

앱이 새 버전을 확인하고 사용자의 선택으로 업데이트하며, 업데이트 전후 목표·기록·식물·창 설정·알림 설정을 유지한다. 업데이트 파일은 소스와 분리된 공개 [배포 저장소](https://github.com/Heo-zip/hanzanhae-releases)에 둔다. 다른 기기 동기화, 데이터 수동 백업 UI, 앱스토어 배포는 범위 밖이다.

## 사용자 흐름

1. Mac 패키지 앱은 시작 30초 뒤와 이후 6시간마다 조용히 새 버전을 확인한다. 메뉴 막대에서 직접 확인할 수도 있다.
2. 새 버전이 있으면 사용자에게 다운로드 여부를 물어본다. 거절하면 현재 앱을 계속 사용한다.
3. 다운로드가 끝나면 재시작 여부를 묻고, 사용자가 선택했을 때만 저장소를 정리한 뒤 업데이트한다.
4. 네트워크나 다운로드 실패 시 기존 앱과 기록을 유지하고 재시도할 수 있다. 사용자가 직접 확인했을 때는 결과를 알려준다.

## 데이터와 프로세스

- SQLite는 기존 `app.getPath('userData')/hanzanhae.sqlite` 경로를 유지하고 앱 번들 안에 넣지 않는다. 앱 이름과 번들 식별자를 함부로 바꾸지 않는다.
- 기존 스키마 이전과 트랜잭션·상위 버전 거부를 보존한다. 스키마가 바뀌는 기존 데이터는 이전 전 SQLite 백업을 만들고, 백업 실패 시 이전하지 않는다.
- 메인 프로세스에서만 업데이트를 확인하고 사용자 기록을 전송하지 않는다. GitHub 요청에는 네트워크 주소와 `electron-updater`가 생성하는 무작위 단계 배포 식별자가 전달될 수 있다.
- 한잔해 창은 평소 닫기 시 숨기므로 업데이트 종료 이벤트에서 실제 종료 상태를 표시한다. 재시작 요청 전 생기 저장 확인이 실패하면 설치를 멈추며, 실제 종료 시 SQLite 연결을 닫는다.
- 버전 다운로드는 사용자가 동의한 경우에만 시작한다. 다운로드 후 앱 종료 시 자동 설치하지 않고, 사용자가 재시작을 선택해야 설치한다.
- 공개 파일 제공처·Developer ID 서명·Apple 공증이 준비돼야 실제 Mac의 서명된 두 버전 간 업데이트를 검증할 수 있다.

## 검증

- 자동·수동 확인, 새 버전 없음·거절·다운로드·재시작·오류·중복 요청을 격리된 테스트로 확인한다.
- 임시 DB에서 기존 기록·설정과 이전 스키마를 새 버전으로 열고 보존 여부를 확인한다.
- 업데이트 전 저장소 정리와 창 닫기 처리, 정리 실패 시 설치 중단을 확인한다.
- 실제 서명된 DMG 설치·업데이트·재실행과 기존 사용자 데이터 유지 확인은 서명과 배포 파일 준비 여부를 명시한다.
