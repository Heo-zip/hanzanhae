# 생기 개편 테스트 마이그레이션 오류

## 증상

스키마 10을 추가한 뒤 이전 버전을 흉내 내는 저장소 테스트 7개가 실패했다. `no such table: vitality_gains`, 마이그레이션 직후 생기 기대값 불일치, 최신 버전 거절 테스트의 버전 번호 불일치가 났다.

## 원인

- 테스트는 새 DB를 만든 뒤 표를 지워 옛 버전을 만든다. 새 표 `vitality_gains`를 지우지 않아 재이전 때 충돌했고, 일부 문장에는 중복 삭제가 들어가 없는 표를 지우려 했다.
- 버전 5 이전 데이터의 생기는 그때의 기본값 80으로 만들어지는데, 새 시작값 60을 기대했다.

## 해결

옛 버전을 만드는 모든 테스트에서 `vitality_gains`를 한 번씩 지우고, 버전 5 이전 데이터는 생기 80을 기대하도록 고쳤다. 최신 버전 거절 테스트는 11로 올렸다.
