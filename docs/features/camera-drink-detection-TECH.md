## 2. 전체 흐름과 파일 위치

```text
설정 화면: 사용자가 카메라 켜기
    ↓
useCameraDetection: 로컬 모델 로딩 → 카메라 영상 요청 → 프레임 분석
    ├─ 얼굴: 첫 번째 얼굴의 입 위치
    ├─ 물체: cup / bottle / wine glass 상자와 점수
    └─ 손: 손 랜드마크와 좌·우 구분
    ↓
거리 관측 → 병 상자 비율 변화 → 후보 상태 기계
    ↓
설정 미리보기의 후보 수 증가
    └─ useCameraRecord → recordDrinkAction(add) → 오늘 마신 횟수 +1 (#47)
```

- `useCameraDetection.ts`: 실행·정리, MediaPipe 호출, 진단 값, 영상 등록 유사도 비교를 담당한다. 후술하는 단계별 입력과 결과는 현재 코드에 대한 설명이다.
- `drinkDetection.ts`: 여러 화면 프레임의 값을 받아 `near` / `away` / `unknown`과 후보 발생 여부를 계산한다. 입력에 관한 판정만 검사할 수 있으므로 이미지 속 물체가 실제로 병인지 알지 못한다.
- `tumblerCalibration.ts`, `Dashboard.tsx`, `dashboard.css`: 영상 등록 안내와 영역, 결과·상태 미리보기를 제공한다.
- `src/main/index.ts`, `src/main/camera/security.ts`: 대시보드 메인 프레임의 영상 권한과 앱에 포함한 모델·WASM 접근을 제한한다. `electron-builder.yml`은 macOS 카메라 사용 목적을 지정한다.
- `tests/camera-detection.test.mjs`, `tests/tumbler-calibration.test.mjs`, `tests/camera-security.test.mjs`: 각각 순수 판정, 등록 안내, 허용 경로·요청의 자동 테스트다. 실제 카메라 정확도 테스트는 아니다.

### 3-2. 입과 용기·손의 거리

`getObservation()`은 얼굴·용기·손의 현재 결과를 `near`, `away`, `unknown`으로 줄인다. 좌표는 화면 너비와 높이를 각각 1로 정규화한 값이다. 가로·세로 비율이 다른 화면에서는 아래 거리의 해석에도 영향을 줄 수 있다.

- `MouthTracker`: 얼굴이 잠시 사라지면 마지막 입 위치를 최대 **3,000ms** 사용한다. 그보다 오래되면 입을 모르는 상태다.
- `isNearMouth`: 입에서 용기 상자 외곽까지의 정규화 좌표 거리 `≤ 0.07`이면 입 근처라고 본다. 입이 상자 안이면 거리 0이다.
- `HandCupEvidence`: 손 관절점 중 하나와 용기 상자 사이 거리 `≤ 0.08`이면 해당 좌·우 손의 시간을 기억한다. 이후 **3,000ms** 이내 같은 손의 점이 입과 `≤ 0.18`이면 손이 입 근처라는 보조 신호를 만든다.
- 입 위치가 없으면 `unknown`. 용기 상자가 입 가까이에 있거나 위 보조 손 신호가 있으면 `near`. 그 외 얼굴이 감지되면 `away`, 얼굴도 없으면 `unknown`이다.

**주의:** 이 `near`는 물을 마셨다는 뜻이 아니다. 이전 실험에서는 입 주변 신호만으로 실제 횟수가 추가되어 오인식이 발생했다. 현재 최종 후보는 이 보조 신호만으로 만들어지지 않는다.

### 3-3. 기울임 후보의 실제 계산

`TiltTracker`는 각도를 추정하지 않는다. 반환된 용기 중 점수가 0.3 이상인 **첫 번째 상자**를 이용해, 화면에서 상자의 가로세로 비율이 세운 기준보다 커졌는지 비교한다. 여러 용기 중 실제 사용 중인 병을 식별하거나 안정적으로 추적하는 구현은 아니다.

```ts
const ratio = (box.width * frameAspect) / box.height
const reference = 평균(세운 기준 비율)
const tilted = ratio >= reference * 1.35 && ratio >= reference + 0.15
```

- `box.width`, `box.height`는 정규화된 상자 크기이고 `frameAspect = videoWidth / videoHeight`를 곱해 화면 비율을 보정한다. 이 비율은 **상자의 크기**이지 병 자체의 실제 각도가 아니다.
- `away`일 때 비율이 `≤ 0.9`인 값을 최근 최대 5개 모으고, 3개 이상 있을 때 평균을 기준으로 사용한다. 기준 수가 부족하거나 관측이 `unknown`이면 `unknown`이다.
- 마지막으로 유효한 상자를 본 후 **15초**가 지났거나, 이전 중심과 현재 중심의 정규화 거리 `> 0.35`이면 기준을 비운다. 이는 같은 병임을 확인하는 추적이 아니라 단순 초기화 조건이다.
- 현재 프레임의 첫 얼굴 입 위치와 선택한 용기 상자가 가까워야 `cupAtMouth`다. 과거 입 위치나 손만으로 이 조건을 통과시키지 않는다. 따라서 마시는 순간 입이나 병이 가려지면 실제 마시기도 놓칠 수 있다.
- `cupAtMouth && tilt === 'tilted'`면 최종 행동 관측은 `near`, 그렇지 않을 때 원래 관측이 `away`면 `away`, 나머지는 `unknown`이다.

사용자는 기울였을 때 텀블러뿐 아니라 생수병도 인식이 끊긴다고 확인했다. 현재의 상자 비율 방식이 얼마나 맞는지, 다른 손·용기·각도에서 어떤 오류가 나는지는 아직 측정하지 않았다. 기울임이 감지됐다는 문구는 실제 3차원 각도 측정이나 음용 확정이 아니다.

### 3-4. 후보 횟수 상태 기계

`DrinkDetection.observe()`는 현재 관측과 시간을 받아 실험 후보를 최대 한 번 발생시킨다.

| 상태 | 현재 전이 |
| --- | --- |
| `waiting` | `near`가 들어오면 후보가 시작되고 `candidate`로 전환한다. |
| `candidate` | `near`가 **800ms** 이상 이어지고 마지막 후보 이후 **8,000ms**가 지났으면 후보 1회를 발생시키고 `latched`가 된다. `away` 또는 마지막 `near`로부터 **500ms 초과**한 미확인 관측이면 `waiting`으로 돌아간다. |
| `latched` | `away`가 **1,800ms** 연속되면 `waiting`으로 돌아간다. 그 외 관측은 내려놓은 것으로 확정하지 않는다. |

등록 실험이 진행 중일 때는 후보 상태 기계를 새로 만들어 연습 동작을 후보로 세지 않는다. 후보가 나오면 React의 `detectedCount`만 증가하며 카메라 종료·다시 시작 시 초기화한다. **실제 물 마신 횟수나 SQLite 데이터는 변경하지 않는다.**

## 4. 영상 등록 유사도는 별도 실험

- 화면의 중앙 고정 상자 `{ x: 0.28, y: 0.15, width: 0.44, height: 0.7 }`를 사용한다. 위치와 크기는 화면에 대한 비율이다.
- 준비 3초 후 12초 동안 세우기·돌리기·기울이기를 안내한다. 등록 중 약 500ms 간격으로 상자 안 화면을 `mobilenet_v3_small.tflite`의 ImageEmbedder에 넣어 특징 벡터를 얻는다. 최소 3개 벡터가 있어야 등록 완료다.
- 완료 후 약 1,000ms 간격으로 현재 고정 영역의 벡터와 등록 벡터 각각의 코사인 유사도를 비교해 **최댓값**을 표시한다. 벡터는 메모리에 있고 카메라를 끄면 삭제한다.
- 영상의 배경과 손도 특징에 반영될 수 있다. 고정 영역은 용기 추적기가 아니며, 유사도는 음용 확률이 아니다. **현재 유사도는 후보 수나 실제 물 기록 판정에 전혀 연결되지 않는다.** 등록이 완료됐다는 의미는 특징 벡터를 일정 개수 모았다는 뜻이다.

## 6. 측정 기준과 트러블슈팅 기록

현재까지 실제 시도 횟수·분석 대상 프레임·정답·환경이 체계적으로 기록되지 않아 **신뢰할 수 있는 기준 정확도는 없다**. 앞으로 다음과 같이 남긴다. 원본 영상·좌표·특징 벡터를 저장하는 계측은 지금 구현돼 있지 않다. 영상 저장은 기본 제외하며, 별도 저장이 필요하다면 명시적인 동의와 보관·삭제 방식을 정한다.

### 6-2. 실험 2 보완: 얼굴을 놓치는 경우 (2026-11-16, 실측 전)

사용자가 실험 2를 기존 방식보다 낫다고 확인했다. 다만 ① 고개를 완전히 젖힐 때, ② 좌우로 고개를 돌린 채 마실 때, ③ 정면에서 텀블러 바닥이 얼굴을 가릴 때 잘 잡히지 않는다고 제보했다. 코드상 세 경우 모두 Face Landmarker가 얼굴을 놓쳐 고개 각도와 입 위치가 함께 사라지고, 손 판단이 1.5초 넘게 끊기면 동작을 버리는 구조였다. 아래 세 가지를 같은 실험에 추가했다. 측정 수치는 아직 없다.

1. **자세 모델로 대체**: 얼굴 모델 값이 없으면 Pose Landmarker의 코(0)·귀(7·8)·입꼬리(9·10)·어깨(11·12)를 쓴다(가시도 0.5 이상, 어깨 둘 다 필요). 고개 젖힘은 `(귀 평균 높이 − 코 높이) ÷ 어깨 너비`이며, 평소 값(손이 입 근처가 아닐 때 최근 20프레임 중앙값)보다 **0.06** 이상 크면 젖힌 것으로 본다. 각도가 아닌 비율이다. 입 근처는 입꼬리 중간에서 `어깨 너비 × 0.6`을 얼굴 높이 대신 쓴다.
2. **가림을 마시는 자세로 판단**: 얼굴이 사라진 뒤 3초 안에, 용기를 잡은 상태에서 손 점이 직전 얼굴 상자에서 얼굴 높이의 30% 이내에 있거나 용기 상자가 직전 얼굴 상자와 겹치면 `가림`으로 판단한다. 가림은 손이 입 근처이고 고개를 젖힌 것으로 처리해 0.6초 유지 조건을 그대로 적용한다.
3. **얼굴 모델 기준 완화**: `minFacePresenceConfidence`, `minTrackingConfidence`를 기본 0.5에서 **0.3**으로 낮췄다.

판단 우선순위는 얼굴 모델 → 가림 → 자세 모델 → 모름(이전 상태 유지)이다. 미리보기 칩은 판단에 쓴 출처(`얼굴`, `자세로 대체`, `얼굴 가림`, `얼굴 놓침`)를 표시한다.

### 6-3. 고개 방식만 남기기 (2026-11-16)

사용자가 6-2까지 보완한 고개 방식이 가장 좋다고 확인해, 비교용으로 함께 돌던 기존 방식을 제거했다.

- 제거: `DrinkDetection`·`MouthTracker`·`HandCupEvidence`·`TiltTracker`·`drinkCandidate`·`isNearMouth`, 텀블러 영상 등록(`tumblerCalibration.ts`, ImageEmbedder, 설정 화면 등록 버튼·유사도 표시, `tests/tumbler-calibration.test.mjs`), 모델 `blaze_face_short_range.tflite`·`hand_landmarker.task`·`mobilenet_v3_small.tflite`.

## 7. 재개 시 순서와 완료 조건

1. 남아 있는 미커밋 실험 변경의 보존·통합 방식을 사용자와 검토하고, 실제 비교 가능한 버전 식별 방법을 정한다.
2. 같은 조건에서 빈손/병 잡은 손, 세운 생수병/기울인 생수병, 실제 음용/비음용 동작의 **기준선부터** 측정한다.
3. 신호 결합·짧은 추적 끊김·용기 추적·방향 추정 중 한 가지씩 변경하고 같은 조건의 지표와 비용을 비교한다. 병이 보이지 않는 동안 실제 각도를 안다고 가정하지 않는다.
4. 참가자·용기·장면이 분리된 평가로 오감지·놓침·중복과 사용자 경험을 확인한다. 필요 시 확인 버튼 방식을 평가한다.
5. 충분히 검증되기 전에는 자동 기록을 연결하지 않는다. 기록 정책과 허용 수준을 정한 뒤 기존 기록 IPC·저장 실패·중복 방지·macOS 권한과 배포 패키지를 확인한다.

## 실제 기록 연결 (#47, 2026-11-16)

- 방식: 확인 버튼 없이 자동 기록하고 되돌리기를 제공한다(사용자 선택). 텀블러 ml·식물 성장은 바꾸지 않고 횟수만 +1 한다.
- `useCameraDetection(hasGoal, onSip)`: `sip.fired`일 때 콜백만 부른다. 프레임·좌표·각도는 넘기지 않는다.
- `useCameraRecord`: 감지마다 새 요청 ID로 `recordDrinkAction(add)`을 보내고, 결과에 따라 왼쪽 아래 토스트로 8초간 안내한다(남은 시간 막대, 오늘·목표 횟수 표시).
  - 성공: "카메라가 1회 기록했어요 · 되돌리기". 되돌리기는 저장된 기록이 아직 최근 기록일 때만 `undo`를 보낸다. 그 뒤 다른 기록이 있으면 오늘 화면의 최근 횟수 취소를 안내한다.
  - 목표·날짜 변경(`STALE_STATE`·`VALIDATION_ERROR`): 저장하지 않았다고 안내한다.
  - 저장 실패: 실패로 안내한다. 감지 1회는 재시도하지 않는다(성공처럼 보이지 않게 함).
- 중복: 같은 동작은 `SipDetector`의 5초 재감지 대기로 막는다. 요청마다 ID가 달라 저장소의 중복 요청 확인과 겹치지 않는다.
- 검증: 타입·린트, 저장소 테스트 43개·카메라 테스트 16개 통과. 빌드한 화면 + 가짜 API에서 기록·되돌리기·저장 실패·목표 변경·다른 기록 뒤 되돌리기 안내를 확인했다. 실제 카메라로 마셨을 때의 기록은 사용자 확인이 남았다.

### 빠르게 마시기 대응 (#47 사용자 QA 후, 2026-11-16)

### 용기 인식 재설계 A·B (#47, 2026-11-16)

- 문제: 1단계(컵이나 병을 들어요)가 잘 안 잡힌다. 화면 전체(640×480)를 320×320으로 줄여 찾으니 손에 든 병이 작고, 손가락에 가려지고, 빠르게 들면 흔들린다. COCO 학습 모델은 탁자 위에 세운 컵·병 위주다.
- A. 손 주변 확대 재검출: `handZoomRegions`가 가슴 높이 이상(어깨 높이 + 어깨 너비 1배 이내)으로 올라온 손마다 어깨 너비 1.2배의 정사각형 영역을 만든다. 이 영역을 320×320으로 키워 별도 IMAGE 모드 EfficientDet-Lite0(같은 모델 파일, 점수 0.2, 최대 3개)로 다시 찾고, 결과를 원래 화면 좌표로 되돌린다. 프레임당 최대 2회 추가 실행.
- B. 집어 드는 순간 기억: 최근 1.5초 안에 보였던 용기 상자 자리에 손 점이 오면, 집는 손에 가려 상자가 사라져도 잡은 것으로 본다.
- 근거 표시: `ContainerHold.source`가 `touch`(화면 전체)·`zoom`(확대)·`pickup`(가려지기 직전 상자)·`mouth`(입에 닿음) 중 무엇으로 통과했는지 알려 주고, 미리보기 1단계 아래에 문구로 보여준다. 확대 영역은 보라색 점선, 확대에서 찾은 상자는 `(확대)` 표시.
- 검증: 카메라 테스트 23개 통과, 빌드 통과. 가짜 카메라 영상으로 모델 4개 로딩과 분석 루프가 오류 없이 도는 것을 확인했다. 사람이 있는 실제 영상에서 확대 재검출이 얼마나 잡는지는 측정 전이다.
- 측정 계획: 생수병·텀블러·머그 × 빠르게·천천히 각 10회, 1단계 통과 `n/N`과 근거별 비율, CPU 사용률.

### 제자리 용기 구분 (#47 사용자 QA 후, 2026-11-16)

- 문제: 병이 손에 없고 화면에 놓여 있기만 해도 빈손을 입에 대고 고개를 젖히면 기록됐다.
- 원인: `ContainerHold`가 손 점과 상자의 거리(≤ 0.05)만 보고 6초 기억했다. 놓인 병 옆을 손이 스치거나, 입에 댄 손 주변 확대 영역에 같은 병이 들어오면 1단계가 통과됐다.
- 변경: 손·입이 닿지 않은 채 보인 상자를 '제자리 용기'로 기억(10초, IoU ≥ 0.3)하고, 그 자리에 있는 상자에는 `touch`·`zoom`·`mouth`를 인정하지 않는다. 제자리 용기는 손이 잡은 뒤 손을 든 동안 그 자리가 600ms 이상 비어야 `pickup`으로 인정하고, 손이 떠났는데 그대로 있으면 후보를 버린다. `useCameraDetection`은 손을 든 상태(확대 영역이 있음)를 함께 넘긴다.
- 검증: 카메라 테스트 26개 통과(오감지 재현 테스트는 이전 코드에서 실패), 저장소 43개, 타입·린트·빌드 통과. 실제 카메라 확인 전.

### 빨대 음용 측정 (2026-11-16, #47)

- 문제: 빨대로 마시면 고개를 거의 젖히지 않아 3단계에서 놓친다(오류 보고서 남은 제한).
- 계획: 고개 젖힘 대신 "들고 온 용기가 입에 붙은 채 입술을 오므림"을 다른 경로로 인정한다. 기준값은 실제 측정 후 정한다.
- 이번 변경(측정만, 판정 미연결): Face Landmarker에 `outputFaceBlendshapes: true`를 켜고 `mouthPucker`(입술 오므리기)·`mouthFunnel`(입술 모으기)을 꺼낸다(`mouthShape`). `MouthShapeMeter`가 현재 값과 최근 3초 최고값을 돌려주고, 설정의 카메라 화면 범례 아래에 소수 둘째 자리로 표시한다. 새 모델은 추가하지 않았다.
- 측정 방법: 빨대로 마시기, 병을 입에 대고 말하기, 그냥 말하기, 가만히 있기를 각각 여러 번 하고 두 값의 3초 최고값을 기록한다. 텀블러가 입을 가릴 때 값이 흔들리는지도 본다.
- 검증: 카메라 테스트 28개, 타입·린트·빌드 통과. 가짜 카메라 영상에서 모델 로딩과 측정 줄 표시('–')를 확인했다. 사람 얼굴의 실제 값은 측정 전이다.
