# 생기 기준 개편과 정원 감지 알림 결과

> 상태: 구현·자동 검사·임시 프로필 앱 점검 완료. 새 식물 사진과 실제 카메라·화면 잠금 확인 전. 기준은 [결정 020](../DECISION_RECORD.md)과 [생기 기준](../product.md#생기-기준)을 따른다.

## 구현

- 스키마 10: `drink_actions.source`, `vitality_gains`를 추가했다. 기록마다 실제로 오른 생기를 저장하고 횟수·텀블러 취소 시 그만큼 되돌린다.
- 생기 계산: 사용 중 -10/시간, 자리 비움 -2/시간. 메인이 `powerMonitor`의 화면 잠금·잠자기 이벤트로 상태를 바꾸고, 1분 저장 주기보다 긴 공백은 처음 3분만 사용 중으로 본다.
- 카메라 상태: 메인이 `setCameraActive`로 받은 상태를 기억해 카메라 기록 주장을 검증하고 텀블러 증가량(+15/+30)을 정한다.
- 정원: 카메라 감지 기록이 저장되면 물방울·파문·화분 튕김 연출과 감지 표시·되돌리기 버튼을 8초 보여 준다. 정원은 15초 안의 최신 카메라 기록만 되돌릴 수 있다. 어느 쪽에서 되돌려도 다른 쪽 버튼이 사라진다.
- 사진: 생기를 5단계로 묶는 `plantFrame`을 만들고 새 사진 전까지 기존 사진과 색 조절로 연결했다. 물 준 사진 2장은 더 이상 쓰지 않는다(파일은 남겨 둠).
- 알림 문구는 시든 사진 구간(생기 50 미만)부터 다급한 문구를 쓴다.

## 실제 테스트 결과

- `npm run typecheck`, `npm run lint` 통과.
- 저장소 46, 카메라 28, 위치 4, 알림 12, 업데이트 9개 테스트 통과. 새 테스트: 사용 중·자리 비움·종료 속도와 재실행, 저장 공백, 버튼 5분 제한·카메라 무제한·취소, 텀블러 +15/+30과 상한·취소, 정원 되돌리기 제한.
- 빌드한 앱을 임시 프로필로 실행하고 개발자 도구 프로토콜로 확인했다(카메라는 켜지 않음): 시작 60 → 버튼 66 → 5분 안 버튼 66 → 카메라 기록 72 → 정원 되돌리기 66 → 텀블러(카메라 켬) 81 → 텀블러(카메라 끔) 100. 카메라가 꺼진 상태의 카메라 기록은 `VALIDATION_ERROR`. 정원 감지 연출·표시·되돌린 뒤 사라짐을 스크린샷으로 확인했다.

## 미확인

- 실제 카메라로 감지했을 때의 정원 연출과 대시보드 안내 연동.
- 실제 화면 잠금·잠자기 뒤 생기 감소 속도.
- 새 식물 사진 20장(제작 전). 연출 중 화분 테두리에 얇은 선이 잠깐 보이는 현상은 사진 교체 때 함께 확인한다.

## 배운 개념

- 저장 직후 화면 상태는 한 번 늦게 따라온다. 다른 창의 되돌리기를 감지할 때는 그 기록이 화면에 반영된 것을 본 뒤에만 사라지게 해야 방금 보여 준 버튼이 바로 사라지지 않는다.
- 주기 저장 간격보다 긴 공백은 프로세스가 멈춰 있던 시간이다. 잠자기 이벤트를 놓쳐도 이 공백을 자리 비움으로 보면 밤새 시드는 문제를 막을 수 있다.
