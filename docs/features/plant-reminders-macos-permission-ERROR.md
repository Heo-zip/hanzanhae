# macOS 테스트 알림 표시 거부

- 상태: 권한 요청 흐름 개선 및 사용자 알림 표시 확인 / 관련: [알림 PLAN](plant-reminders-PLAN.md)
- 환경: macOS arm64, Electron 44.11.1, 임시 사용자 데이터와 별도 앱 식별자

## 현상

개발 Electron에서 테스트 알림을 요청하자 `failed` 이벤트에 `Notifications are not allowed for this application`이 반환됐다. 임시 데이터와 별도 식별자를 쓰는 ad-hoc 서명 macOS 패키지에서도 테스트 알림은 실패했다. 앱 실행 방식으로 직접 실행과 macOS 일반 앱 실행을 모두 시도했으나 표시 성공은 확인하지 못했다.

## 확인한 범위와 미확인 사항

- `Notification.isSupported()`는 true였지만 실제 요청은 거부됐다. 지원 여부가 알림 권한을 뜻하지는 않는다.
- 테스트 앱의 macOS 알림 권한 또는 앱 등록·서명 상태가 관련될 수 있으나 현재 증거만으로 원인을 확정하지 않는다. 시스템 설정을 변경하거나 권한을 임의로 허용하지 않았다.
- 실제 성공·클릭은 미검증이다. 설정 화면의 테스트 알림은 실패 시 오류를 안내하고, 자동 알림 실패는 마지막 성공 시각으로 저장하지 않는다.
- Electron 문서는 macOS 알림에 서명이 필요하다고 설명한다. [Electron 알림 문서](https://www.electronjs.org/docs/latest/api/notification)
- 사용자는 처음에 시스템 알림 설정에서 한잔해를 찾지 못했다. 기존 코드는 알림을 켜더라도 조건이 충족돼 실제 알림을 보내거나 테스트 버튼을 누르기 전까지 시스템 권한 요청이 지연될 수 있었다.

## 추가 수정과 검증

- 알림을 켜고 저장할 때 즉시 확인 알림을 요청한다. 설정은 저장됐지만 표시가 실패하면 화면에 안내한다. 확인 알림이 표시되면 시각을 저장해 자동 알림과 겹치지 않도록 한다.
- 작업 폴더의 별도 macOS 네이티브 진단 앱에서 사용자가 권한 요청을 허용했고, 권한 상태가 `notDetermined`에서 `authorized`로 바뀌었다.
- 개인 데이터와 분리된 작업 폴더의 ad-hoc 서명 Electron 테스트 앱에서도 알림을 켰을 때 `show` 이벤트가 발생했다. 이는 실제 사용자 화면의 배너 표시·클릭을 확인했다는 뜻은 아니다.
- `/private/tmp`의 테스트 앱은 거부되고 작업 폴더의 테스트 앱은 권한 요청이 허용되는 차이를 관찰했다. 앱 경로·등록·권한 상태 중 무엇이 차이를 만들었는지 단정하지 않는다.
- 사용자가 별도 데이터로 실행한 한잔해 테스트 앱에서 설정을 저장한 뒤 실제 알림이 잘 뜨며, 알림을 누르면 대시보드가 열린다고 확인했다.

## 다음 확인

다른 사용자 환경의 권한·서명 동작과 정해진 간격 경과 후 자동 알림은 추가로 확인한다. 이전 `/private/tmp`의 실패 원인은 확정하지 않는다.
