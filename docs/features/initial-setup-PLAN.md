## 목적과 범위

사용자가 첫 실행에 하루 목표량과 한 잔 용량을 직접 정하고, 앱을 다시 실행해도 목표·용량·초기 식물을 이어서 보게 한다. 로그인이나 서버는 사용하지 않는다.

**이번 범위:** SQLite 연결과 앱 데이터 저장 기반, 최초 설정 입력·검증, 목표·설정·초기 식물의 원자적 저장, 시작 상태 조회와 재실행 복원, 실패 안내.

**제외:** 실제 한 잔 기록, 물주기 성공 애니메이션, 취소, 목표 중단·재생성 UI, 생기·성장 계산과 통계. 기능이 연결되기 전 물 기록 버튼은 비활성화한다. 기존 목표가 중단된 상태를 최초 실행과 구분하는 시작 상태는 다루되, 목표 재생성의 상세 기능은 후속이다.

## 사용자 흐름과 화면

1. 앱이 로컬 저장소를 열고 설정 완료 여부와 활성 목표를 조회한다. 조회 중 입력·기록을 막는다.
2. 처음 실행이면 필수 설정 화면에 하루 목표량과 한 잔 용량을 입력한다. 건너뛸 수 없고 고정된 목표를 임의로 제시하지 않는다.
3. 양은 ml 단위 양수 정수로 검사한다. 빈 값·0·음수·소수는 입력 위치에 안내한다.
4. 시작을 누르면 중복 입력을 막고 목표·용량·초기 식물·설정 완료 상태를 함께 저장한다. 저장이 실패하면 입력값과 설정 화면을 유지하고 재시도하게 한다.
5. 성공한 결과만 화면에 반영한다. 다음 실행에서도 저장된 값을 불러온다. 기록이 없을 때 가짜 섭취·성장·통계를 실제 기록으로 표시하지 않는다.

| 시작 상태                | 동작                                                               |
| ------------------------ | ------------------------------------------------------------------ |
| 최초 설정 전             | 필수 설정 화면 표시, 기록 차단                                     |
| 설정 완료·활성 목표 있음 | 저장된 설정과 식물을 불러와 정원·대시보드 표시                     |
| 설정 완료·활성 목표 없음 | 최초 사용자와 구분하고 기존 데이터 보존, 새 목표 설정 전 기록 차단 |
| 저장소 열기·읽기 실패    | 최초 사용자로 간주하거나 데이터를 초기화하지 않고 오류·재시도 안내 |

설정 UI는 `design/dashboard.html`의 새 첫 실행 시안을 따른다. 키보드 이동, 입력 라벨·오류 연결과 포커스 표시를 확인한다.

## 데이터와 Electron 연결

- 앱 데이터 폴더에 SQLite 파일을 두는 방향이다. 정확한 경로·라이브러리·마이그레이션 방식은 Electron·macOS 패키징 검증 후 결정한다.
- 저장 대상은 활성 목표와 시작 시각, 한 잔 용량, 최초 설정 완료 상태, 초기 식물 상태다. [데이터 설계](../database.md)의 테이블·필드명은 구현 전 초안이다.
- 목표·설정·초기 식물과 최초 설정 쓰기 요청의 중복 처리 결과는 하나의 트랜잭션으로 저장한다. 활성 목표는 최대 하나다.
- Renderer는 입력과 상태를 보여주고, Preload는 허용된 조회·최초 설정 함수만 제공한다. Main은 발신자·입력을 다시 검사하고 저장을 처리한다. 원시 IPC·파일 시스템·임의 SQL은 노출하지 않는다.
- 내부 API 초안의 `completeOnboarding` 및 시작 상태 조회 방법을 구현 시 구체화한다. 같은 요청의 중복 처리와 충돌은 [IPC 설계](../ipc-api.md#쓰기-요청과-날짜)를 따른다.
- 개발용 예시 데이터는 실제 저장 결과와 구분한다. 다른 제품의 계정·서버·네트워크 처리는 도입하지 않는다.

## 오류와 복원

| 상황                            | 화면·앱 처리                                          |
| ------------------------------- | ----------------------------------------------------- |
| 빈 값·0·음수·소수               | 해당 입력을 수정하도록 안내하고 저장하지 않음         |
| 저장 도중 오류                  | 전체 저장 취소, 입력 유지와 재시도 안내               |
| 빠른 중복 클릭·같은 요청 재시도 | 중복 처리를 막고 목표·초기 식물이 여러 개 생기지 않음 |
| 저장소 열기·조회 실패           | 데이터 초기화 없이 오류 안내, 기록 차단               |
| 설정 완료 후 목표가 없음        | 기존 기록을 지우거나 최초 설정 상태로 바꾸지 않음     |
| 앱 종료 후 재실행               | 저장된 목표·용량·식물을 다시 읽음                     |

## 구현·검증 순서

1. SQLite 후보의 Electron 버전·Mac 칩·개발 실행 및 패키징 호환성을 확인하고 선택 근거를 기록한다. 네이티브 모듈 사용 시 현재 `npmRebuild: false`를 재검토한다.
2. DB 파일 경로, 초기 스키마·마이그레이션·트랜잭션을 구성한다. 필요한 데이터부터 구현하며 전체 스키마가 완성된 것으로 취급하지 않는다.
3. 시작 상태 조회와 최초 설정 IPC를 구현하고 타입·입력·발신자를 검증한다.
4. 설정 화면의 입력·오류·저장 상태와 시작 화면 전환을 연결한다. 실제 기록은 후속 작업까지 비활성화한다.
5. 정상·유효하지 않은 입력·중복·중간 저장 실패·조회 실패·재시작을 검증한다. 실제 macOS 개발 실행과 패키징·설치·재실행 결과를 각각 기록한다.

## 완료 조건

- [x] 최초 설정을 건너뛰지 못하며 양수 정수 두 값을 사용자가 직접 입력한다.
- [x] 목표·용량·초기 식물·설정 상태와 중복 요청 처리 결과가 함께 저장된다.
- [x] 개발 Electron 재실행 후 값이 복원되고, 저장소 테스트에서 설정 완료·목표 없음과 최초 설정 전을 구분한다.
- [x] 저장 실패 시 일부 데이터나 성공 UI가 남지 않으며 입력과 재시도가 가능하다. 임시 DB에 실패를 주입해 실제 Electron 화면의 입력 유지·재시도와 저장소 롤백을 확인했다.
- [x] 손상된 저장소 데이터를 빈 상태로 오인하지 않고 기존 데이터를 보존한다.
- [x] 물 기록 미구현 상태에서 기록을 할 수 없고 예시 데이터가 실제 이력처럼 보이지 않는다.
- [x] 타입 검사·린트·빌드 및 관련 정상·실패·재실행을 검증하고 실제 Mac·패키징의 미확인 범위를 기록한다.
- [x] 발생한 실제 오류는 ERROR에 기록했다. 기능 결과 REPORT는 2026-11-14에 기존 기록을 근거로 소급 작성했다.

개발 Electron·SQLite 자동 테스트와 arm64 앱 묶음 생성은 확인했다. 패키지 충돌 원인을 수정했고 로컬 ad-hoc arm64 패키지의 첫 설정과 재실행 복원을 [확인했다](initial-setup-packaged-qa-timeout-ERROR.md). [결과 보고서](initial-setup-REPORT.md)에 검증 범위와 남은 한계를 정리했다. 배포 서명·공증과 DMG 설치 검증은 남아 있다.
