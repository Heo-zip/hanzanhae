# 기능 기획서: 카메라 물 마시기 감지

## 기본 정보

- 기능: 카메라를 이용한 물 마시기 횟수 감지
- 상태: **실험 재개 · 고개·손목 단계 판정으로 전환** (2026-11-16). 사용자 확인 후 기존 방식을 제거했다. 상세는 [기술 기록 6-1~6-3](camera-drink-detection-TECH.md). 자동 기록은 아직 연결하지 않았다.
- 이전 상태: 구현 보류 · 설계 및 검증 방법 정리 (2026-11-15)
- 관련: [Issue #36](https://github.com/Heo-zip/hanzanhae/issues/36), [기술 구현 기록](camera-drink-detection-TECH.md), [인식 오류 기록](camera-drink-detection-recognition-ERROR.md)
- 현재 실험 코드는 작업 브랜치에 남아 있으며 커밋·병합되지 않았다. 사용자가 오작동을 확인해 자동 저장은 중지했다. 아래 제안은 구현 완료나 정확도 보장을 뜻하지 않는다.

## 목표와 범위

물을 자주 마시도록, 사용자가 선택해 카메라를 켜면 텀블러를 들고 입에 가져가 마시는 행동을 감지해 물 마신 **횟수**를 기록하는 것을 장기 목표로 한다. 텀블러를 비웠을 때의 **용량 기록과 식물 성장**은 사용자가 직접 물뿌리개를 눌러 처리한다.

우선 검토 범위는 카메라에 잡힌 뚜껑 있는 텀블러를 입에 대고 기울이는 행동이다. 빨대·컵을 기울이지 않는 행동이나 가려진 상태의 완전한 인식은 이번 실험의 성공으로 간주하지 않고 별도로 검토한다. 카메라 영상만으로 물인지, 삼켰는지, 몇 ml인지 확정하지 않는다.

로그인과 서버 없이 Mac에서 처리한다. 카메라는 사용자가 직접 켜고, 기본 꺼짐 및 앱 재시작 후 꺼짐을 유지한다. 사용자는 언제든 끌 수 있어야 한다.

## 실제 실험 결과

| 시도 | 확인된 내용 | 남은 한계 |
| --- | --- | --- |
| 얼굴과 컵·병 감지 | 텀블러가 기울 때 컵이나 얼굴이 사라졌고 실제 음용 두 차례를 놓쳤다. | 검출 자체가 끊기면 거리만으로 행동을 판단하기 어렵다. |
| 손 추적 | 빈손에서는 손 표시가 잘 된다고 확인했다. 이후 사용자는 생수병을 잡으면 손 인식이 잘되지 않는다고 제보했다. | 손이 입에 가까운 행동은 음용 외에도 많다. 생수병이 손을 가리는 영향은 아직 수치로 측정하지 않았다. |
| 화면 영역 영상 등록 | 등록과 유사도 점수는 표시됐다. | 상자 안 배경과 손도 비교되며, 텀블러만 찾아 추적하거나 모델을 새로 학습한 것은 아니다. |
| 생수병 탐지 | 사용자는 생수병은 잘 인식하지만 기울이면 병 인식이 잘 안 된다고 제보했다. | 테스트 횟수와 인식 유지율은 측정하지 않았다. 기울임을 판단하는 것도 어렵다고 했다. |
| 컵과 입의 거리 | 컵이 보일 때 마신 것으로 기록되는 오작동을 사용자가 확인했다. | 거리만으로 기울임과 음용을 알 수 없다. |
| 상자 가로세로 비율 변화 | 자동 저장 대신 화면에 후보만 표시하는 실험을 만들었다. 이후 사용자가 오작동이 많다고 확인했다. | 상자 비율은 실제 기울기 각도가 아니며, 원근·크기·가림에도 변한다. 정확한 오작동 유형별 횟수는 기록되지 않았다. |

영상·사진은 저장하지 않았다. 현재 실험의 자동 테스트 통과는 실제 카메라에서의 정확도를 뜻하지 않는다.

## 앞으로 검토할 감지 흐름 — 제안

```text
카메라 켜기 → 얼굴·손·용기 관찰 → 용기를 든 손과 입 방향 움직임 확인
→ 입 근처에서 일정 시간 유지 → 용기를 내리는 동작 확인
→ 충분한 근거가 있을 때만 후보 1건 → 검증된 정책에 따라 사용자 확인 또는 자동 기록
```

1. **기준 잡기**: 카메라에서 얼굴과 손을 확인하고, 사용자가 자주 쓰는 용기를 여러 각도에서 볼 수 있는지 시험한다. 화면 고정 상자 유사도만으로 용기 등록 성공을 확정하지 않는다.
2. **접근**: 한 손이 용기와 함께 움직이며 입 근처로 향하는지, 여러 프레임의 흐름을 본다. 단일 사진이나 한 프레임으로 기록하지 않는다.
3. **마시는 자세 후보**: 용기가 실제로 기울었다는 근거가 있는지 검토한다. 용기 모델의 검출 결과, 손의 움직임, 얼굴 방향 등은 각각 불확실하므로 조합 방법은 실험으로 정한다. 용기 상자 비율은 보조 신호일 뿐 확정 기준으로 쓰지 않는다.
4. **가림**: 얼굴이나 용기가 잠시 가려지면 그 직전의 신호와 시간 흐름을 참고하되, 확인할 근거가 부족하면 `판단 불가`로 처리한다. 오래된 위치와 손만으로 성공 처리하지 않는다.
5. **종료와 중복 방지**: 실제 마신 동작과 입에서 내려놓는 흐름을 하나의 행동으로 묶는 방법을 검토한다. 화면 깜빡임이나 잠깐 가려짐이 여러 번의 기록으로 이어지지 않아야 한다. 유지 시간과 재감지 간격은 실측 후 정한다.
6. **기록**: 정확도 검증 전에는 DB에 아무 기록도 남기지 않고 후보만 표시한다. 검증 후에도 사용자 확인을 거쳐 기록할지, 자동 기록을 허용할지는 실험 결과를 보고 결정한다. 지금 당장 확정된 동작이 아니다.

### 손 가림과 기울임에 대한 추가 아이디어 — 미검증

- **기울임이 없어도 되는 신호를 먼저 본다.** 병을 들기 전 인식 → 입 쪽으로 이동 → 입 주변에서 잠시 유지 → 내려놓기의 연속 흐름을 탐색한다. 이는 음용의 단서일 뿐, 병을 입에 대기만 해도 비슷해 오인식 가능성이 있다. 기울임이 불확실한 경우 자동 기록을 확정하지 않고 판단 불가 또는 사용자 확인 후보로 둔다.
- **잠시 감지가 끊길 때** 병을 마지막으로 본 위치와 그 전후 움직임을 짧게 이어 볼 수 있다. 시간·거리 제한이나 재연결 대상은 데이터로 결정한다. 이는 추적 가설이며 가려진 동안 병의 위치나 기울기를 안다고 뜻하지 않는다. 재연결이 틀리거나 병과 손이 모두 사라지면 판단 불가로 전환한다.
- **손 신호 의존도 비교**: 빈손과 병을 잡은 손의 감지 유지율을 먼저 측정한다. 손이 놓치는 조건에서는 팔·손목 등 다른 신호와 병 단독 움직임을 비교할 수 있지만, 팔 움직임만으로 마신 것으로 판단하지 않는다. MediaPipe Pose 사용은 가능성을 검토하는 선택지이며 기존 앱에 추가된 기능이 아니다.
- **기울임을 직접 추정하는 선택지**: 병 입구와 바닥, 병의 윤곽을 찾을 수 있는 모델 또는 기하학적 방법을 별도로 실험한다. 한 프레임의 화면상 방향은 원근·손 가림·투명 병·카메라 각도에 영향을 받고 실제 3차원 각도와 다르다. 별도 모델·데이터의 비용도 비교해야 하며 병이 사라지면 각도를 계산할 수 없다.
- **단계별 실패 원인 분리**: 병 감지, 병 추적 유지, 손 감지, 입 주변 접근, 음용 후보 판단을 각각 측정한다. 앞 단계의 정보가 없을 때 뒷 단계가 성공할 것이라고 가정하지 않는다.

| 선택지 | 기대 | 한계와 판단 기준 |

| 행동 인식용 별도 모델 | 프레임 여러 장을 함께 고려해 동작을 구분할 가능성이 있다. | 사용자·용기·환경이 다양한 동의된 학습/평가 데이터, 모델 크기, 기기 성능과 라이선스를 검토해야 한다. 정확도 개선은 미확인이다. |

### 용기 인식(1단계) 재설계 순서 — 2026-11-16 결정

1. **A 손 주변 확대 재검출 + B 집어 드는 순간 기억**: 구현 완료(v3.2). 실제 인식률 측정 전.
2. **측정**: 생수병·텀블러·머그 × 빠르게·천천히 각 10회, 1단계 통과 `n/N`과 근거별 비율, CPU.
3. **C 내 물병 등록**: 2에서 계속 놓치는 용기가 있을 때. 손 주변을 잘라 등록 특징과 비교한다.
4. **D 전용 모델 학습**: 데이터·라이선스 비용 때문에 마지막 선택지.

자세한 원인과 설정값은 [오류 보고서 v3.2](camera-drink-detection-recognition-ERROR.md#v32--용기-인식-재설계-ab-2026-11-16-47)에 있다.

한 방법을 미리 확정하지 않는다. 가벼운 기존 모델 조합을 먼저 평가하고 부족한 원인이 용기 검출인지 행동 판단인지 나눠서 다음 실험을 선택한다. 빠른 해결이 어렵다면 수동 횟수 기록을 계속 사용한다.

## 사용자 화면과 제어 — 제안

- 설정: 카메라 기능의 목적과 영상의 로컬 처리 범위, 오인식 가능성을 알려주고 사용자가 켠다. 권한 거부·장치 없음·중지 방법을 표시한다.
- 인식 확인 화면: 얼굴·손·용기 감지, 접근·기울임 후보, 판단 불가, 후보 횟수를 구분해 보여준다. 얼굴 점은 표시하지 않는다. **후보 횟수는 실제 기록과 분리한다.**
- 진단 정보는 사용자가 직접 열 때만 보인다. 모델 추론이나 좌표 정보가 일반 사용 화면을 복잡하게 만들지 않는다.
- 검증 이후 실제 기록을 연결할 때는 기록 성공·실패를 구분하고, 잘못 추가된 횟수는 기존 최근 횟수 취소 흐름을 쓴다. 실패를 성공처럼 표시하지 않는다.
- 첫 사용에서 용기 등록을 필수로 둘지, 앱 종료 후 등록 정보를 유지할지, 확인 버튼과 자동 기록 중 무엇을 쓸지는 **미정**이다.

## 데이터·Electron·개인정보

- 기존 실험의 영상과 프레임은 메모리에서 처리하고 저장·전송하지 않는다. 향후 평가를 위해 녹화가 필요하다면 별도의 명확한 동의, 보관 위치·기간·삭제 방법을 먼저 정하며 기본값은 저장 안 함이다.
- 특징 벡터와 랜드마크도 사람과 환경에 관한 정보를 담을 수 있으므로 무해하다고 가정하지 않는다. 현재 용기 유사도 특징은 메모리에만 두고 카메라 종료 시 삭제한다. 향후 영속 저장 여부는 별도로 결정한다.
- 마이크는 사용하지 않는다. 권한 거부·카메라 끄기·장치 연결 해제·앱 종료 시 카메라 트랙과 모델을 정리한다. 화면 숨김, 앱 재시작, 다른 앱의 화상회의와 카메라 사용 충돌을 확인한다.
- 향후 실제 기록 시 Renderer는 판단 결과만 전달하고, Main은 기존 허용된 IPC와 SQLite 기록 흐름을 사용한다. 활성 목표, 한국 날짜, 중복 요청과 저장 실패를 확인한다. 프레임·좌표를 IPC 기록 데이터나 로그에 포함하지 않는다.
- 웹 모델 실행이 UI를 막는지 측정하고 필요하면 Worker 등으로 분리한다. 이는 추후 설계이며 지금 구현됐다는 뜻은 아니다.

## 검증 계획 — 나중에 진행

### 1. 조건과 정답을 먼저 준비

- 참가자·기기·용기·거리·조명·가림 여부를 구분한다. 뚜껑 있는 텀블러와 일반 컵을 포함하고, 가능하면 여러 사람과 다른 Mac 환경을 사용한다.
- 실제 마신 행동은 참가자가 직접 횟수와 시간을 기록한다. 다른 동작도 미리 분류하며, 카메라 결과와 정답을 따로 보관한다. 기본적으로 원본 영상은 보관하지 않는다.
- 최소한 같은 사람이 텀블러를 **그냥 들기, 카메라에 비추기, 세운 채 입에 대기, 입 주변에 손만 가져가기, 말하기·얼굴 만지기**와 실제 마시기를 분리해 시험한다. 각 조건의 횟수와 관찰 시간을 빠짐없이 기록한다.
- 초기 탐색용 데이터와 나중에 평가할 사람·영상·동작을 분리한다. 같은 녹화의 인접 프레임을 양쪽에 섞어 정확도가 부풀지 않게 한다. 별도 평가 데이터가 없으면 독립 검증이 아님을 밝힌다.

### 2. 지표를 따로 확인

- **놓침률** = 실제 마신 횟수 중 감지하지 못한 횟수 ÷ 실제 마신 횟수.
- **잘못 감지한 횟수** = 마시지 않았는데 후보 또는 기록이 생긴 횟수. 동작별 횟수와 일상 사용 시간당 오감지 수를 함께 본다.
- **중복** = 실제 한 번의 마시기에 후보가 여러 번 생긴 횟수. 인식 지연, 가림·용기별 결과도 함께 기록한다.
- 프레임 처리 속도, CPU·메모리, 카메라가 켜진 동안 배터리 영향과 UI 끊김은 동일한 Mac·시간·실험 조건으로 비교한다. 추측 수치는 결과로 적지 않는다.
- 예를 들어 실제 10번 중 7번을 찾았다면 3번을 놓친 것이다. 마시지 않는 동안 두 번 울렸다면 그 두 번은 별도로 오감지로 센다. 둘 중 하나만 좋아져도 성공으로 판단하지 않는다.

### 실험 기록 및 트러블슈팅 작성 방법

실험을 시작할 때마다 한 가지 변경만 적용해 같은 조건의 이전 버전과 비교한다. 검출 점수나 한두 장면만으로 전체 정확도라고 표현하지 않는다. 아래 표는 작성 양식이며 실제 결과를 채우기 전에는 `미측정`으로 둔다.

| 항목 | 기록 내용 |
| --- | --- |
| 실험 ID·날짜·버전 | 코드 버전 또는 커밋, 모델과 설정. 미커밋이면 구분 가능한 기록 |
| 목표·가설 | 예: 병을 잡은 손의 가림으로 인식이 끊기는지 확인. 추정과 사실 구분 |
| 조건 | 생수병 또는 텀블러, 사람 수, 손 방향, 카메라 위치·거리, 조명, 카메라 해상도와 처리 빈도 |
| 실제 행동과 정답 | 행동별 실제 횟수·관찰 시간과 정답 표시 방법. 개인정보·영상은 기본 저장하지 않음 |
| 기준선 | 수정 전의 검출·놓침·오인식·중복. 실제 수치가 없으면 미측정 |
| 변경 | 비교 가능한 한 가지 변경, 사용된 모델·설정과 변경 이유 |
| 결과 | 같은 기준·조건의 수정 후 수치, 분자/분모, 횟수와 단위 및 남은 문제 |
| 해석·다음 실험 | 좋아진 지표와 나빠진 지표, 작은 표본·환경 의존성, 후속 가설 |

- 병 감지 유지율: 병이 화면에 실제로 보이는 **평가 대상 프레임** 중 병을 감지한 프레임 수 / 전체 대상 프레임 수. 세운 상태·기울인 상태를 따로 기록한다. 분석된 프레임을 기준으로 하며 실제 보여진 모든 프레임이나 연속 추적 성공을 뜻하지 않는다.
- 손 감지 유지율: 손이 평가 대상인 분석 프레임 중 손을 감지한 프레임 수 / 전체 대상 프레임 수. 빈손과 생수병을 잡은 상태를 따로 기록한다. 가려져 손이 안 보이는 장면의 정답 정의는 미리 정한다.
- 추적 끊김: 실제 같은 용기를 보여주는 연속 구간에서 감지가 끊긴 횟수·지속 시간과 재연결 성공/시도 수를 기록한다. 단순한 프레임 유지율과 별도 지표다.
- 음용 판단은 행동 단위로 실제 음용 성공/시도, 미음용의 잘못 감지/시도, 일반 작업 중 시간당 오감지, 한 행동의 중복을 각각 기록한다. 프레임 감지 유지율을 음용 정확도로 바꾸지 않는다.
- 숫자는 실제 실험이 끝난 뒤 기록하며 `n/N`, 환경, 측정 방법, 작은 표본의 한계와 비교 불가능한 조건을 함께 남긴다. 개선 전 기준값이 없으면 임의로 만들지 않고 이후 기준 측정부터 시작한다.
- 트러블슈팅 문서는 **초기 설계 → 실제 문제와 재현 → 원인 가설과 검증 → 적용한 해결책 → 전후 수치와 부작용 → 남은 한계**로 정리한다. 해결하지 못한 실험도 결과 그대로 남긴다. 실제 오류는 기존 ERROR 기록에 연결한다.

### 3. 자동 기록 연결 전 조건

- `컵만 보임`, `세운 채 입에 댐`, `손만 움직임`이 각각 잘못 기록되지 않는지 실제 환경에서 확인한다.
- 여러 번의 실제 마시기와 가림·다른 용기에서 누락과 중복, 일반 작업 중 시간당 오감지를 측정하고 조건별 결과와 표본 수를 남긴다.
- 허용할 오감지·놓침 수준은 실제 데이터를 보고 정한다. 현재 임시 시간·비율과 위의 예시는 합격 기준이 아니다.
- 데이터 보존·권한·카메라 해제와 부하를 확인하고, 사용자와 결과를 검토하기 전까지 실제 기록 연결 및 기능 완료·병합을 하지 않는다.

## 향후 작업 순서

1. 현재 오류와 실험 코드를 다시 확인하고, 추가 실험을 진행할지 결정한다.
2. 검출 누락·오감지 사례와 정답 기록 방식을 준비한 뒤 기존 방식을 기준선으로 측정한다.
3. 한 번에 한 가지 신호나 모델을 바꿔 같은 조건에서 비교한다. 필요할 때만 추적·별도 행동 모델을 검토한다.
4. 분리된 평가 조건으로 재검증하고, UI·사용자 확인 방식 및 저장 여부를 확정한다.
5. 충분한 결과가 나오면 기록 IPC·예외 처리·패키지 및 실제 Mac 검증을 진행하고 결과 보고서를 작성한다.
