# 개발 중 오류 보고서: 물 마시기 동작 누락과 오인식

> 트러블슈팅 작성용 기록이다. 초기 방법부터 현재 방법까지의 판정 기준과 모든 설정값, 사용자가 실제로 확인한 현상을 남긴다. 제거한 코드는 저장소에 커밋된 적이 없어 이 문서와 [기술 기록](camera-drink-detection-TECH.md) 1~5절이 유일한 기록이다. 정확도 수치(놓침률·오감지율)는 **측정하지 않았다**. 아래 수치는 설정값·코드 규모·모델 크기·자동 테스트 수이며 인식 성능이 아니다.

## 기본 정보

- 기능명·오류 식별명: `camera-drink-detection` · `recognition`
- 발생·작성: 2026-11-15 최초 발생, 2026-11-16 개선과 정리
- 심각도: 보통 (물 기록 자동화의 정확도 문제. 자동 저장을 끈 뒤에는 데이터 오염 없음)
- 상태: **개선 중 · 수치 검증 전**. v3(고개·손목 단계)가 이전 방식보다 낫다고 확인했고, v3.2에서 1단계(용기 인식)를 재설계했다.
- 관련: [Issue #36](https://github.com/Heo-zip/hanzanhae/issues/36), [Issue #47](https://github.com/Heo-zip/hanzanhae/issues/47), [PLAN](camera-drink-detection-PLAN.md), [TECH](camera-drink-detection-TECH.md), [결과 리포트](camera-drink-detection-REPORT.md)
- 브랜치: `feature/camera-drink-detection` (기준 HEAD `12d1a12`, 카메라 코드는 미커밋)

## 환경

- macOS 26.6.1, Apple Silicon arm64, Node.js 24.14.1, Electron 44.11.1, `@mediapipe/tasks-vision` 0.10.21
- 개발 실행(`npm run dev`), 패키징 앱은 미확인
- 카메라 요청: 이상적 값 640×480, 10fps, 오디오 없음. 실제 해상도·fps는 기록하지 않았다.
- 분석 주기: `setInterval` 250ms(초당 최대 약 4회), 새 프레임이 없으면 건너뜀
- 모든 모델은 Renderer에서 CPU로 실행. 영상·좌표·특징 벡터는 저장·전송하지 않는다.

## 버전별 방법과 설정값

### v1 — 입과 용기의 거리 (초기 방법)

- 모델: BlazeFace short range(`blaze_face_short_range.tflite`, 229,746B), EfficientDet-Lite0(`efficientdet_lite0.tflite`, 7,254,339B)
- 얼굴: `minDetectionConfidence` 0.5, 첫 얼굴의 `keypoints[3]`을 입으로 사용
- 용기: `categoryAllowlist` `cup`·`bottle`·`wine glass`, `maxResults` 5
- 입 근처: 입에서 용기 상자 외곽까지 정규화 거리 **≤ 0.07**
- 상태 기계(`DrinkDetection`): `near`가 **800ms** 이어지면 기록, 기록 간 **8,000ms** 재감지 금지, `near` 끊김 허용 **500ms**, 내려놓음 확정은 `away` **1,800ms** 연속
- 결과: P1 (2/2 놓침, 표본 2회)

### v1.1 — 낮은 점수 사용과 입 위치 유지

- 용기 화면 표시 기준 `scoreThreshold` **0.2**, 판정 사용 기준 **0.3**
- `MouthTracker`: 얼굴이 사라져도 마지막 입 위치를 **3,000ms** 사용
- 결과: P2 발생. 자동 저장 호출(`recordDrinkAction`)을 제거했다.

### v1.2 — 손 추적과 미리보기

- Hand Landmarker(`hand_landmarker.task`, 7,819,105B), `numHands` 2, VIDEO 모드
- `HandCupEvidence`: 손 관절점이 용기 상자 **≤ 0.08**이면 그 손(좌·우)을 기억, **3,000ms** 안에 같은 손의 점이 입 **≤ 0.18**이면 보조 `near`
- 선택형 미리보기: 얼굴(초록)·손(주황)·용기(파랑, 점수 %)·상태 칩 5개(얼굴·컵·손·거리·기울임)
- 결과: 빈손 인식은 좋음, P3 발생

### v1.3 — 텀블러 영상 등록 (판정에는 미연결)

- MobileNet V3 Small ImageEmbedder(`mobilenet_v3_small.tflite`, 4,117,670B), `l2Normalize` true, IMAGE 모드
- 초기: 드래그로 고른 상자 → 손을 따라 움직여 기준을 알기 어렵다는 피드백
- 개선: 고정 안내 상자 `{ x: 0.28, y: 0.15, width: 0.44, height: 0.7 }`, 준비 **3초**, 수집 **12초**(세우기 0~4초 → 돌리기 4~8초 → 기울이기 8~12초), 수집 간격 **500ms**, 최소 **3개** 벡터
- 비교: **1,000ms**마다 현재 상자 벡터와 등록 벡터들의 코사인 유사도 최댓값 표시
- 결과: 등록·점수 표시는 동작. 손·배경도 점수에 섞이며 텀블러 유무·기울기 구분력은 미확인. 자동 기록에 쓰지 않았다.

### v1.4 — 상자 비율로 기울임 후보

- `TiltTracker`: 첫 번째 0.3 이상 용기 상자의 `ratio = (width × 화면비) ÷ height`
- 세운 기준: 입 근처가 아닐 때 `ratio ≤ 0.9`인 값 최근 **5개**, **3개** 이상이면 평균을 기준
- 기울임: `ratio ≥ 기준 × 1.35` **그리고** `ratio ≥ 기준 + 0.15`
- 기준 초기화: 마지막 상자 후 **15초** 경과 또는 상자 중심 이동 **> 0.35**
- 후보: 현재 프레임에서 입과 용기가 가깝고(0.07) 기울임일 때만 `near`
- 프레임당 모델: 얼굴·용기·손 3개 + 등록 중 임베더
- 결과: P5. 사용자 요청으로 실험 보류(2026-11-15)

### v2 — 고개·손목 단계 판정 (2026-11-16)

- 추가 모델: Face Landmarker(`face_landmarker.task`, 3,758,596B, `outputFacialTransformationMatrixes`), Pose Landmarker Lite(`pose_landmarker_lite.task`, 5,777,746B, `numPoses` 1)
- 비교를 위해 v1.4와 **같은 프레임에서 나란히** 실행하고 후보 수를 따로 표시(프레임당 모델 5개)
- 고개 각도: 변환 행렬(열 우선) `data[9]`의 `asin` → 위를 볼수록 + (부호는 사용자 화면 확인 대상이었음)
- 평소 각도: 손이 입 근처가 아닐 때 최근 **20프레임 중앙값**, 최소 **5프레임**
- 입: 얼굴 랜드마크 13·14 중간. 얼굴 높이: 랜드마크 10~152 거리(화면비 보정)
- 손: Pose 15~22번(손목·새끼·검지·엄지), 가시도 **≥ 0.5**
- 손이 입 근처: 가장 가까운 손 점까지 거리 ÷ 얼굴 높이 **≤ 1**
- 용기 잡음(`ContainerHold`): 손 점이 용기 상자(점수 0.2 이상) **≤ 0.05**, **6,000ms** 기억
- 단계(`SipDetector`): 대기 → 용기 잡은 손이 입 근처 → 평소보다 **12°** 이상 젖힘이 **600ms** → 손이 입에서 **400ms** 멀어지면 후보 1회. 손 판단이 **1,500ms** 넘게 끊기거나 **20,000ms** 지나면 버림, 후보 간 **5,000ms**
- 결과: 사용자가 기존보다 낫다고 확인. 이어서 P6 제보

### v2.1 — 얼굴을 놓치는 경우 보완

- 얼굴 모델 `minFacePresenceConfidence`·`minTrackingConfidence` 기본 0.5 → **0.3**
- 자세 대체(`poseHead`): 어깨 11·12가 둘 다 보여야 함(가시도 0.5). 고개 = `(귀 7·8 평균 높이 − 코 0 높이) ÷ 어깨 너비`, 평소보다 **0.06** 이상이면 젖힘. 입 = 9·10 중간, 얼굴 높이 대신 `어깨 너비 × 0.6`
- 가림(`FaceCover`): 얼굴이 사라진 뒤 **3,000ms** 안에, 용기를 잡은 상태에서 손 점이 직전 얼굴 상자에서 `얼굴 높이 × 0.3` 이내이거나 용기 상자가 직전 얼굴 상자와 겹치면 가림 → 손 입 근처 + 고개 젖힘으로 처리
- 판단 우선순위: 얼굴 모델 → 가림 → 자세 모델 → 모름(이전 상태 유지)
- 결과: 사용자가 "지금 방법이 딱 좋다, 제일 좋다"고 확인

### v3 — 고개 방식만 남김 (현재)

- v1~v1.4 판정·텀블러 등록·BlazeFace·Hand Landmarker·MobileNet 제거, 앱 내부 모델 허용 목록에서도 차단
- 프레임당 모델 **3개**(용기·얼굴·자세), v2.1 설정값 그대로

### v3.1 — 실제 기록 연결과 빠르게 마시기 대응 (2026-11-16, #47)

- 실제 기록: 감지 1회를 `recordDrinkAction(add)`으로 오늘 마신 횟수에 저장. 확인 버튼 없이 자동 기록 + 토스트 되돌리기(사용자 선택, 결정 019)
- 시작 조건 완화: 손이 입에 오면 용기 없이 시작. 용기는 과정 중 한 번 보이면 인정, 끝까지 못 봤으면 내린 뒤 **1,500ms** 안에 보일 때 인정
- 용기 상자가 입에 닿으면(**≤ 0.05**) 잡은 것으로 봄
- 고개 기준 **12° → 8°**, 젖힘 유지 **600ms → 300ms**. 재감지 대기 5,000ms는 유지
- 결과: 사용자 QA에서 P8 확인. 1단계가 병목으로 남음

### v3.2 — 용기 인식 재설계 A·B (2026-11-16, #47)

현재 인식 구조(재설계 전): 250ms마다 화면 전체를 EfficientDet-Lite0(COCO, 입력 320×320, `cup`·`bottle`·`wine glass`, 점수 ≥ 0.2)에 넣고, 자세 모델 15~22번 손 점(가시도 ≥ 0.5)이 상자에서 **≤ 0.05**이면 잡음, **6,000ms** 기억.

검토한 선택지와 판단:

| 안 | 방법 | 판단 |
| --- | --- | --- |
| A | 손 주변을 잘라 320×320으로 키워 다시 검출 | **채택**. 새 모델·등록 없이 같은 병을 4~6배 크게 봄 |
| B | 가려지기 직전 상자 기억(집어 드는 순간) | **채택**. 세운 병은 잘 잡히는 점(P4)을 활용 |
| C | 내 물병 등록(손 주변 잘라 MobileNet 임베딩 유사도) | 보류. A·B로 부족한 용기가 있을 때. v1.3 실패 원인(고정 큰 상자라 배경 섞임)을 손 주변 자르기로 줄일 수 있음. 등록 UX·특징 저장 여부 결정 필요 |
| D | 손에 든 텀블러·병 전용 모델 학습 | 보류. 수백 장 라벨 데이터, 모델 크기, 라이선스 비용이 큼 |
| 공통 | 1단계를 관문 대신 점수로(근거 확실도에 따라 고개 기준 조정) | 후속 검토 |

적용 설정값:

- `handZoomRegions`: 어깨 둘 다 가시도 ≥ 0.5일 때만. 손 점 평균 위치가 어깨 높이 + 어깨 너비 **1배** 이내(가슴 위)인 손마다 한 변 = 어깨 너비 **1.2배**의 정사각형(화면비 반영), 화면 밖이면 안으로 이동
- 확대 검출기: 같은 `efficientdet_lite0.tflite`, IMAGE 모드, 점수 ≥ **0.2**, 최대 **3개**, 입력 **320×320**. 분석 1회당 최대 **2번** 추가 실행
- 상자 기억: 최근 **1,500ms** 안 상자 자리에 손 점이 **≤ 0.05**이면 `pickup`
- 근거 우선순위: `touch`(화면 전체) → `zoom`(확대) → `mouth`(입) → `pickup`(직전 상자). 미리보기 1단계 아래 문구와 보라 점선(확대 영역)으로 표시
- 결과: 자동 테스트와 가짜 카메라 영상의 모델 로딩·분석 루프 확인. **사람 영상 인식률은 미측정**

### v3.3 — 제자리 용기 구분 (2026-11-16, #47)

- 원인(P9): "손 근처에 상자가 있다"를 "손에 들었다"와 같게 봤다. 화면에 놓인 병은 손이 가까이 지나가기만 해도 근거가 됐다.
- 바꾼 기준: **용기가 손을 따라 움직였는가**로 판단한다.
  - 손·입이 닿지 않은 채 보인 상자는 **제자리 용기**로 기억한다(최대 **10,000ms**, 같은 자리 판정 IoU **≥ 0.3**).
  - `touch`·`zoom`·`mouth`는 **제자리 용기가 아닌** 상자에만 인정한다. 들고 온 병은 원래 자리에서 벗어나 있으므로 통과하고, 놓인 병은 막힌다.
  - `pickup`(집어 들기)은 제자리 용기에 손이 닿은 뒤, **손이 가슴 위로 올라간 동안** 그 자리가 **600ms 이상 연속으로 비어야** 인정한다. 손이 떠났는데 병이 그 자리에 그대로 보이면 후보를 버린다. 잡은 뒤 **4,000ms** 안에 자리가 비지 않아도 버린다.
- 테스트: 오감지 재현(놓인 병 + 손 스침 + 확대 영역에 같은 병 + 빈손 입·고개 젖힘 → 0회), 놓인 병에 입이 다가감 → 잡지 않음, 만지고 떼기 → 잡지 않음, 잡고 들어 자리 비움 → `pickup`, 들고 온 병이 입에 닿음 → `mouth`. 새 테스트 4개는 v3.2 코드에서 실패함을 확인했다.
- 남은 위험: 처음부터 손에 든 채 화면에 들어온 병은 제자리 기억이 없어 바로 인정된다(의도). 병을 들지 않고 손 앞 공중에 든 다른 물체는 COCO가 컵·병으로 보면 통과할 수 있다. 제자리 병이 검출 깜빡임으로 600ms 이상 사라지고 그 사이 손이 들려 있으면 `pickup`으로 오인할 수 있다. 실제 사람 영상으로는 아직 측정하지 않았다.

### v3.4 — 빨대 음용 측정 준비 (2026-11-16, #47)

- 판정은 바꾸지 않았다. 입술 오므리기(`mouthPucker`)·모으기(`mouthFunnel`) 표정 값(0~1)과 최근 **3,000ms** 최고값을 미리보기에 표시한다.
- 다음: 빨대 음용·병 대고 말하기·말하기·가만히 있기의 값을 비교해 기준값을 정한 뒤, 고개 젖힘 대신 쓰는 경로를 추가한다.

### v3.5 — 빨대 음용 판정 연결 (2026-11-16)
