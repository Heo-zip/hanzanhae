- 기능: 식물 생기·성장 / 상태: 구현·자동 검증 완료, 사용자 직접 QA 미확인 / 우선순위: MVP 핵심
- 이슈: [#7](https://github.com/Heo-zip/hanzanhae/issues/7) / 브랜치: `feature/plant-growth-vitality`
- 기준: `design/garden.html`, `design/dashboard.html`, 기능·DB 명세와 결정 004·010.

## 목적과 범위

물을 기록할 때 화분이 생기를 되찾고 목표 달성·초과로 누적 성장한다. 정원과 대시보드에 같은 식물 상태를 표시하고, 물 기록 취소 시 그 기록이 만든 성장만 함께 되돌린다. 통계와 씨앗 수집은 제외한다.

## 정책과 흐름

- 물 기록 전후 총량이 처음으로 목표를 넘으면 기본 성장 1,000점을 부여한다. 해당 잔의 초과분과 이미 목표 이상일 때 기록한 물은 목표량 대비 비율만큼 추가한다. 목표 설정이나 조정만으로는 보상하지 않는다.
- 새싹·어린 잎·무성한 잎·꽃 전환 기준은 각각 0·3,000·7,000·14,000점이다. 값은 사용자와 사용하며 바꿀 임시 기준이다.
- 생기는 최초 80%, 물 기록마다 15%p 회복하고 100%를 넘지 않는다. 실행 중 시간당 2%p, 앱 종료 중 시간당 0.25%p 감소하며 20% 아래로 떨어지지 않는다. 수치는 임시값이다.
- 정원과 대시보드에는 시안의 단계별 이미지와 생기 상태를 적용한다. 기록 취소 시 생기 회복 연출은 되돌리지 않고 성장만 되돌린다.
- 기존 기록은 성장 도입 전 기록이므로 자동 보상하지 않는다. 기능 도입 후 새로운 기록부터 성장 이력을 남긴다.

## 데이터와 Electron 연결

- SQLite 버전 5에 기록별 성장 이력과 생기·계산 시각을 저장한다. 물 기록·성장·생기 갱신과 요청 결과는 같은 트랜잭션이다. 취소는 대상 기록의 성장 이력을 함께 취소한다.
- 실행 중 주기적으로 생기를 저장해 강제 종료 뒤에는 마지막 저장부터 종료 중 속도를 적용한다. 정상 종료와 앱 시작도 시간을 기록한다. 시스템 시계가 뒤로 간 경우 감소시키지 않는다.
- 기존 상태 조회와 창 간 갱신을 재사용한다. 원시 DB나 IPC를 화면에 공개하지 않는다.

## 검증과 완료 조건

- 기존 데이터 이전·유지, 목표 직전/달성/초과, 잔 취소와 전체 취소, 다른 목표·이전 날짜 보존, 중복 요청, 저장 실패 롤백을 검사한다.
- 생기 회복·실행 중/종료 중 시간 흐름·강제 종료와 재실행을 검사한다. 임시 수치를 문서화한다.
- 실제 Electron에서 정원·대시보드의 이미지와 상태, 취소·복원을 확인하고 시안과 비교한다.
- 타입 검사·린트·빌드와 테스트 후 REPORT 및 관련 명세를 갱신한다. 사용자 요청에 따라 검증 결과를 기록하고 병합한다.
