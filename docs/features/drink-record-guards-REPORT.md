# 물 기록 중복 입력 확인 결과

- 2026-11-22 · [#64](https://github.com/Heo-zip/hanzanhae/issues/64) · `feature/drink-record-guards`

## 구현

- 메인이 저장된 횟수로 수동 추가 확인을 판단한다. 연타 또는 카메라 직후에는 이유가 다른 확인 문구를 보여 준다. 확인 요청은 기존 ID를 재사용하며 날짜·목표·최신 기록을 다시 검사한다.
- 텀블러 저장 응답의 용량과 기록 ID로 안내하고, 해당 최신 기록만 되돌린다. DB 스키마는 그대로다.

## 검증

- 저장소 테스트 55개 통과. 3초 경계, 같은 확인 재전송, 카메라 직후, 다른 기록·날짜·목표로 변경, 텀블러 응답 재시도를 추가 검증했다.
- 격리된 Chrome에서 빌드한 화면과 임시 SQLite로 확인창 문구·초기 포커스·Esc·돌아가기·1회 확인·포커스 복귀를 확인했다. 승인 응답이 유실된 뒤 같은 요청을 재시도해도 1회였고, 다른 카메라 기록이 먼저 들어오면 보류한 요청을 거절했다. 텀블러 500ml를 두 번 기록하고 마지막 500ml만 되돌렸다.
- 브라우저 검증은 Electron의 preload 응답을 테스트 연결로 대체했다. 실제 macOS Electron 화면 및 패키지 실사용은 사용자 확인 전이다.

## 유지보수

3초 기준은 메인 저장소의 `DRINK_CONFIRM_WINDOW_MS`에서 관리한다. 기존 요청 영수증은 저장 결과가 유실됐을 때 앱이 같은 입력을 안전하게 다시 보낼 수 있게 한다. [포커스 오류 기록](drink-record-guards-dialog-focus-ERROR.md)
