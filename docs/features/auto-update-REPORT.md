# 자동 업데이트와 데이터 보존 작업 결과

- 이슈: [#29](https://github.com/Heo-zip/hanzanhae/issues/29)
- 계획: [auto-update-PLAN](auto-update-PLAN.md)
- 배포 파일 위치: 소스와 분리된 공개 [hanzanhae-releases](https://github.com/Heo-zip/hanzanhae-releases)
- 상태: 구현과 격리 테스트 완료, Developer ID로 서명한 실제 버전 간 업데이트 검증 전

## 구현

- `electron-updater`로 macOS 패키지의 시작 30초 후와 이후 6시간마다 버전을 확인한다. 메뉴 막대에서 직접 확인할 수 있다.
- 새 버전의 다운로드와 재시작은 사용자가 각각 선택한다. 설치를 미루면 앱을 계속 사용할 수 있고 수동 확인으로 다시 설치할 수 있다. 다운로드 실패·오프라인과 중복 요청을 처리한다.
- 재시작 요청 전 생기 저장을 확인한다. 실패하면 설치를 중단한다. 실제 macOS 업데이트 종료 이벤트에서는 창을 숨기지 않고 닫으며, 종료 시 DB 연결을 정리한다.
- 기존 DB의 스키마를 이전하기 전 `backups/`에 SQLite 일관된 백업을 남긴다. 백업 실패 시 이전을 중단하고, 더 최신 스키마는 변경하지 않는다. 백업 자동 복원이나 다른 기기 동기화는 없다.
- 일반 `build:mac`은 `--publish never`로 패키지만 만든다. 실제 출시 파일 업로드는 별도의 명시적인 배포 절차가 필요하다.

## 검증

| 항목                                              | 결과                                                                                                                  |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `npm run test:update`                             | 9개 통과. 수동·자동 확인, 사용자 선택, 다운로드·설치 실패, 중복 확인, 저장 실패와 macOS 업데이트 종료 이벤트          |
| `npm run test:storage`                            | 37개 통과. 물·성장·정원 위치 보존, WAL이 있는 이전 DB의 백업, 백업 실패, 최신 스키마 거부 포함                        |
| `npm run test:reminders`, `npm run test:position` | 각각 12개와 3개 통과                                                                                                  |
| `npm run lint`, `npm run build`                   | 통과                                                                                                                  |
| 임시 Mac arm64 패키지                             | ad-hoc 서명 ZIP 생성, `app-update.yml`의 공개 배포 저장소 설정과 보조 앱 이름·서명 검사 통과                          |
| 업데이트 확인                                     | 별도 데이터의 이전 테스트 패키지에서 공개 저장소에 릴리스가 없다는 응답까지 확인. 자동 확인 실패는 UI를 방해하지 않음 |
| 실제 버전 간 업데이트                             | 미검증. Developer ID 인증서·공증된 두 버전과 공개 릴리스가 필요                                                       |

## 제한과 다음 단계

- 사용자는 Apple Developer Program에 가입했다고 확인했지만, 이 Mac의 키체인에는 유효한 서명 인증서가 확인되지 않았다. 인증서 발급·설치 후 서명된 두 버전으로 업데이트·재시작·기존 SQLite 보존을 직접 검증한다.
- 공개 배포 저장소는 생성됐지만 릴리스를 업로드하지 않았다. 자동 업데이트 코드를 포함하지 않은 기존 설치본은 새 버전을 자동으로 받을 수 없어 최초 한 번 수동 설치해야 한다.
- 앱의 물 기록은 업데이트 서버로 보내지 않는다. GitHub 업데이트 요청에는 네트워크 주소와 업데이트 라이브러리가 생성하는 무작위 단계 배포 식별자가 포함될 수 있다.
- 백업은 같은 Mac에 있으므로 기기 분실·고장에 대비한 별도 백업이 아니다. 백업 파일은 자동 삭제·복원하지 않는다.
- 외부 릴리스나 커밋·푸시는 사용자의 검토와 요청 범위에 맞춰 진행한다.
