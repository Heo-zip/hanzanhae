# 아키텍처

## 현재 상태

최초 실행 시 하루 목표와 한 잔 용량을 설정하고 SQLite에 저장한다. 이후 앱이 시작되면 목표·용량·초기 식물을 복원한다. React 화면은 preload의 상태 조회·최초 설정 API를 호출하며, 메인은 입력·발신자 검사와 SQLite 트랜잭션을 처리한다. 정원 창의 클릭 통과, 우클릭 숨기기, 전역 단축키와 메뉴 막대도 연결했다. 물 기록과 성장·통계는 아직 구현되지 않았다.

정원은 160×220 크기의 투명 창에 160px 식물 이미지를 표시하고 물뿌리개를 왼쪽 위에 펼친다. macOS에서는 일반 앱 위·Dock 아래의 `floating` 레벨을 사용하고 전체 화면을 포함한 작업 공간에 표시하도록 설정했다. 다시 보일 때 입력 포커스를 가져오지 않는다. 작업 영역이나 연결 화면이 바뀌면 위치만 다시 계산하고, 사용자가 숨긴 창을 자동으로 다시 열지 않는다. Dock 확대·자동 숨김 애니메이션의 실제 영역 추적은 별도 실험으로 남겨뒀다.

## MVP 목표 구조

```text
React 화면 (renderer)
  → preload에서 허용한 함수 호출
  → IPC로 Electron 메인에 요청
  → 입력·날짜·목표 검증 및 제품 규칙 처리
  → SQLite 로컬 저장
  → 결과를 화면에 전달하고 UI 갱신
```

| 영역           | 책임                                               |
| -------------- | -------------------------------------------------- |
| React renderer | 화면, 사용자 입력, 처리 중·오류 상태, 애니메이션   |
| preload        | `contextBridge`로 필요한 기능만 화면에 공개        |
| Electron main  | 창·메뉴 관리, IPC 입력 검증, 제품 규칙과 저장 조정 |
| SQLite         | 이 Mac의 목표·물 기록·성장·설정 보관               |
| shared         | 필요할 때 양쪽에서 공유하는 타입과 순수 규칙       |

IPC는 앱 안의 프로세스 간 메시지 통신이다. 외부 HTTP 서버와는 별개이며, MVP에 NestJS·Supabase·회원가입은 사용하지 않는다.

## 물 한 잔의 흐름

1. 화면은 활성 목표와 한국 날짜를 기준으로 기록을 요청하고 처리 중 중복 입력을 막는다.
2. 메인은 현재 목표·날짜와 요청을 검증하고 저장된 한 잔 용량을 읽는다.
3. 물 기록, 연관 성장·생기와 요청 처리 결과를 하나의 트랜잭션으로 저장한다.
4. 성공하면 갱신된 상태를 반환하고 화면은 물주기 연출을 재생한다. 실패하면 데이터와 성공 UI를 확정하지 않는다.

## 보안과 운영

- 현재 창은 `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`로 생성한다.
- renderer에 원시 IPC, 파일 시스템이나 임의 SQL 실행 기능을 통째로 노출하지 않는다.
- DB는 Electron의 `app.getPath('userData')` 아래 `hanzanhae.sqlite`에 둔다. Electron에 포함된 Node.js의 `node:sqlite`를 사용하며 별도 네이티브 패키지는 추가하지 않았다.
- 로컬 데이터는 다른 기기에 자동 동기화되지 않는다. 백업·삭제·업데이트 시 보존 방식은 별도 검증이 필요하다.
- `node:sqlite`는 현재 Node.js 24에서 실험 단계이므로 Electron·Node 업그레이드 시 호환성을 다시 검증한다. 별도 네이티브 애드온을 추가하면 `npmRebuild: false`도 재검토한다.

구체적인 요청은 [IPC API](ipc-api.md), 데이터 모델은 [데이터 설계](database.md)를 참고한다.
