# 로컬 데이터 설계

> 상태: SQLite 설계 초안. 라이브러리, 실제 DB 파일 경로, 스키마와 마이그레이션은 아직 구현되지 않았다.

## 저장 원칙

- DB 파일은 사용자의 Mac에 있는 앱 데이터 영역에 둔다. 계정이나 원격 서버는 없다.
- 물의 양은 ml 단위 정수다. 기록 시각은 UTC, 하루 구분은 `Asia/Seoul`의 날짜를 기준으로 한다.
- 한국 시간 자정이 되면 오늘 기록 범위만 바뀌고 활성 목표는 유지된다.
- 물 기록과 이에 따른 생기·성장 변경, 요청 처리 결과는 같은 트랜잭션으로 저장한다. 기록을 취소할 때는 관련 성장도 함께 취소하고 취소 요청의 처리 결과를 남긴다.
- 앱 삭제·재설치·업데이트 시 데이터 보존과 백업 방식은 구현 시 검증한다. 자동 동기화는 없다.

## 테이블 초안

| 이름                | 저장할 내용                                                   | 목적                                               |
| ------------------- | ------------------------------------------------------------- | -------------------------------------------------- |
| `goal_sessions`     | 목표 ID, 목표량, 활성·중단 상태, 시작·중단 시각               | 현재와 과거 목표 구분. 활성 목표는 최대 하나       |
| `water_records`     | 기록 ID, 목표 ID, 한 잔의 양, 기록 시각, 한국 날짜, 취소 시각 | 오늘 총량 조회와 기록 취소                         |
| `daily_adjustments` | 목표 ID, 한국 날짜, 입력 전 총량, 입력 총량, 차이, 생성 시각  | 목표 재생성 시 기존 기록에 미기록 섭취량 등을 반영 |
| `growth_events`     | 목표·물 기록 ID, 날짜, 달성·초과 종류, 성장량, 생성·취소 시각 | 어떤 기록이 만든 성장인지 추적하고 취소            |
| `plant_state`       | 식물 종류, 생기, 생기 계산 시각, 최근 실행·종료 시각          | 화면 복원과 경과 시간 반영                         |
| `app_settings`      | 한 잔 용량, 창 위치, 항상 위 표시, 자동 실행, 최초 설정 상태  | 설정 복원                                          |
| `mutation_receipts` | 요청 ID, 작업명, 입력 확인값, 성공 결과, 생성 시각            | 같은 쓰기 요청이 두 번 적용되지 않도록 처리        |

목표는 여러 물 기록·조정·성장 이력과 연결된다. 성장 이력은 원인이 된 물 기록도 참조한다. 테이블명과 세부 열·제약은 구현 전 제안이다.

## 총량과 취소

```text
오늘 총량 = 오늘 취소되지 않은 물 기록의 합 + 오늘 총량 조정의 합
```

예를 들어 기존 기록 500ml에서 새 목표 생성 시 총량 700ml를 입력하면 조정은 +200ml다. 이후 새 목표로 300ml를 기록해 총량이 1,000ml가 되었을 때 **오늘 현재 목표 기록 전체 취소**를 하면 해당 300ml와 관련 성장만 취소되어 700ml가 남는다. 목표, 기존 500ml와 조정 200ml는 유지한다.

재생성 시 입력 총량은 0 이상의 정수이며, 기존 총량보다 적게 입력하면 조정은 음수일 수도 있다. 이후 기록 취소로 조정이 반영된 총량이 음수가 되면 저장을 거절하고, 목표를 중단한 뒤 재생성 과정에서 총량을 다시 확인하도록 안내한다. 조정만 별도로 취소하는 UI는 MVP에 없다.

## 무결성과 복구

- 활성 목표 하나, 양수 용량, 유효한 목표·기록 참조, 동일 기록에 같은 활성 성장의 중복 방지 등을 DB 제약과 메인 검증으로 보장하는 안이다.
- SQLite 연결마다 외래 키 검사를 켠다. 쓰기와 중복 요청 결과를 동일 트랜잭션으로 처리한다.
- 취소는 취소 시각을 기록하는 방식을 제안한다. 유효 기록만 합산한다.
- 정상 종료 후와 강제 종료 후 모두 생기를 복구해야 한다. 강제 종료 시 마지막으로 저장된 시각을 기준으로 보수적으로 재계산하는 방안을 검증한다.
- 성장량·시듦 속도와 목표 재생성 즉시 보상 정책은 아직 미정이다. 구체 수치를 임의로 확정하지 않는다.
