# 로컬 데이터 설계

> 현재 스키마: SQLite 버전 9([#34](https://github.com/Heo-zip/hanzanhae/issues/34)). 물 마신 횟수와 텀블러 용량을 별도로 저장한다. 카메라 감지는 새 테이블 없이 `drink_actions`에 기록하며 영상·좌표·특징값은 저장하지 않는다.

## 보관 원칙

- 데이터는 이 Mac의 `userData/hanzanhae.sqlite`에 저장한다. 회원가입과 원격 서버는 사용하지 않는다.
- 날짜는 한국 시간(`Asia/Seoul`), 시각은 UTC로 저장한다. 자정이 지나면 날짜별 기록이 바뀌지만 목표는 유지한다.
- 스키마 이전 전에 `backups/`에 SQLite 백업을 생성한다. 백업에 실패하면 기존 DB를 수정하지 않는다. 업데이트 시 같은 앱 데이터 경로를 사용하지만 실제 서명된 버전 간 이전은 추가 검증이 필요하다.
- 기존 ml 목표, 물 기록, 성장과 설정을 보존하고 과거 기록을 횟수로 환산하지 않는다. 이전 사용자는 새로운 횟수 목표를 설정해야 한다.

## 주요 테이블

| 테이블 | 보관하는 데이터와 역할 |
| --- | --- |
| `goal_sessions` | 목표 ID, 시작·중단 시각과 `target_count`. 이전 ml 목표는 `target_count`가 비어 있고 기존 `target_ml`을 보존한다. 새 목표의 `target_ml`은 과거 스키마 제약을 위한 호환 값이며 목표로 사용하지 않는다. |
| `drink_actions` | 마신 행동의 ID, 목표, 한국 날짜, 기록·취소 시각과 출처(`button`·`camera`). 오늘의 유효한 행 개수가 횟수다. |
| `vitality_gains` | 횟수·텀블러 기록이 실제로 올린 생기. 기록을 취소하면 그만큼 되돌리고 행을 지운다. 스키마 10에서 추가했고 이전 기록은 소급하지 않는다. |
| `drink_action_receipts` | 횟수 추가·취소 요청과 처리 결과. 재전송 시 중복 처리를 막는다. |
| `water_records` | 텀블러 기록 ID, 당시 용량(ml), 목표, 날짜·시각과 취소 시각. 과거 한 잔 기록도 유지한다. |
| `growth_events` | 물 기록에 연결된 성장 점수. 취소된 기록의 성장은 합계에서 제외한다. |
| `daily_adjustments` | 이전 버전에서 기록한 수동 총량 조정. 총량에 포함하지만 횟수나 성장으로 환산하지 않는다. |
| `app_settings`, `plant_state`, `plant_vitality` | 텀블러 용량, 초기 설정, 식물 생기와 계산 시각. |
| `garden_settings`, `reminder_settings` | 정원 창 위치·표시와 알림 사용 여부·시간·간격. |
| `mutation_receipts`, `settings_receipts`, `cancel_receipts` | 최초 설정, 설정 변경과 물 기록 취소의 중복 요청 방지. 기존 필드명은 호환성을 위해 유지한다. |

## 계산과 취소

- 오늘 횟수는 오늘 취소되지 않은 행동 기록 개수다. 텀블러를 비워도 횟수는 늘지 않고, 횟수 기록만으로 ml가 생기지 않는다. 생기를 올린 횟수(`vitality_gains`에 drink 행이 있는 기록)는 1회당 성장 100점으로 계산하며 따로 저장하지 않는다.
- 오늘 총량은 오늘의 유효한 물 기록과 기존 조정의 합이다. 텀블러 기록은 저장된 용량만큼 추가되고 용량 1ml당 성장 1점의 임시 기준을 적용한다. 이 수치는 실제 사용하며 조정한다.
- 생기는 `plant_vitality`에 마지막 계산 값과 시각을 저장한다. 사용 중·자리 비움 속도와 기록별 증가량은 [생기 기준](product.md#생기-기준)을 따른다.
- 최근 횟수 취소는 오늘의 마지막 행동만 취소한다. 물 기록 취소는 해당 물 기록과 연결된 성장만 제외하고 행동 횟수는 유지한다.
- 전체 취소는 오늘 현재 목표의 물 기록과 오늘 마신 횟수를 함께 취소하고, 그 기록들이 올린 생기와 성장을 되돌린다. 목표, 이전 날짜·다른 목표의 물 기록, 기섭취량 조정은 유지한다. 화면에서 본 횟수와 다르면 거절하고, 취소 후 조정을 포함한 총량이 음수라면 거절한다.
- 일별 달성은 그날 마지막 활성 목표를 기준으로 한다. 새 목표는 행동 횟수, 이전 목표는 당시 ml를 사용하므로 과거 달성을 거짓 행동 횟수로 바꾸지 않는다. 오늘 미달성이면 연속 달성은 어제부터 계산한다.
- 기록과 중복 방지 정보는 같은 트랜잭션에 저장한다. 오래된 목표·날짜·취소 대상은 거절하고 최신 상태를 다시 읽는다.
