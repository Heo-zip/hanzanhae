# 결정 기록

제품과 기술에 영향을 주는 결정을 이유와 함께 기록한다. 기존 항목을 지우지 않고 새 결정과 대체 관계를 추가한다. `확정`, `제안`, `실험`, `변경됨`을 구분하며, 제안은 확정된 기획을 덮어쓰지 않는다.

## 결정 001: 계정 없는 로컬 우선 MVP

- 기록일: 2026-11-13 / 상태: 확정 / 근거: [제품 개요](product.md), 사용자 대화.
- 결정: 회원가입·별도 서버 없이 Electron 앱과 SQLite를 사용한다. 기록과 설정은 이 Mac에 저장한다.
- 이유: 다운로드 후 가볍게 시작하고 오프라인에서도 사용할 수 있도록 한다.
- 영향: 기기 간 자동 동기화는 MVP에 없다. SQLite 연결과 백업·복원 정책은 구현·검증 전이다.

## 결정 002: 최초 설정과 목표 기록의 경계

- 기록일: 2026-11-13 / 상태: 확정 / 근거: [기능 명세](features.md).
- 결정: 사용자가 하루 목표량과 한 잔 용량을 직접 입력하며 최초 설정은 건너뛰지 않는다. 활성 목표가 없으면 물을 기록할 수 없다.
- 이유: 실제 사용자가 정한 기준으로 물을 기록하고, 목표가 없는 상태의 기록을 막는다.
- 영향: 목표 중단 후 재생성은 최초 설정과 다른 흐름이다. 기록과 설정은 저장 성공 후에만 화면에 반영한다.

## 결정 003: 오늘 현재 목표 기록 전체 취소

- 기록일: 2026-11-13 / 상태: 확정 / 근거: [취소 범위](features.md#취소-범위).
- 결정: 한국 시간 기준 오늘 현재 목표의 물 기록과 그 기록이 만든 성장만 취소한다. 목표, 이전 날짜, 다른 목표의 기록·성장과 기섭취량 조정은 유지한다.
- 이유: 목표 자체는 유지하면서 해당 목표로 오늘 기록한 물만 되돌리려는 사용자 의도다.
- 영향: 연관 데이터는 하나의 트랜잭션으로 처리하고 취소 후 총량이 음수가 되면 거절한다.

## 결정 004: 식물의 생기와 성장

- 기록일: 2026-11-13 / 상태: 확정된 방향 / 근거: [식물 반응과 성장](features.md#식물-반응과-성장).
- 결정: 물을 기록하면 생기가 회복되고, 목표 달성 및 초과 기록으로 쌓인 성장량에 따라 외형이 바뀐다. 앱 종료 중에도 아주 천천히 시든다.
- 이유: 물을 자주 마시는 습관과 장기적인 정원 가꾸기를 연결한다.
- 미정: 성장량·단계 기준, 시듦 속도와 일부 보상 정책은 실제 사용하며 정한다.

## 결정 005: 작은 정원과 Dock

- 기록일: 2026-11-13 / 상태: 기본 배치 확정, Dock 추적은 실험 / 근거: [정원과 창](features.md#정원과-창), 사용자 대화.
- 결정: 작은 화분을 오른쪽 아래에 두고, 왼쪽 위에 펼친 물뿌리개가 화분을 향하게 한다. 정원은 일반 앱 위·Dock 아래이며 우클릭·단축키·메뉴 막대로 숨김과 복귀를 제공한다.
- 이유: 작업을 덜 가리고 Dock 조작을 방해하지 않으며 물주기 연출 방향을 유지한다.
- 미정: Dock의 실제 확대·자동 숨김에 따라 움직이는 방식은 감지 안정성 등을 실험한 뒤 정한다. 실시간 추적은 현재 미구현이다.

## 결정 006: 물 마시는 동작 감지

- 기록일: 2026-11-13 / 상태: MVP 이후 실험 / 근거: [제품 개요](product.md#물-마시는-동작-감지-실험).
- 제안: MediaPipe와 카메라로 동작을 추정하고 사용자가 확인한 뒤 기록하도록 검토한다. 기본 꺼짐·로컬 처리와 수동 기록 유지 방향을 제안한다.
- 미정: 인식률, 확인 UI, 개인정보 처리 세부와 실제 도입 여부. 카메라는 음료가 물인지와 실제 섭취량을 확정하지 못한다.

## 결정 007: 최초 설정 SQLite는 Node 내장 모듈 사용

- 기록일: 2026-11-13 / 상태: 구현, 패키지 앱 전체 검증 중 / 근거: Issue #1.
- 결정: Electron에 포함된 Node.js의 `node:sqlite`로 앱 데이터 폴더의 `hanzanhae.sqlite`를 사용한다. 스키마는 `user_version` 1부터 관리한다.
- 이유: 별도 네이티브 애드온 설치·재빌드 없이 로컬 트랜잭션과 파일 저장을 사용할 수 있다.
- 확인: 개발 Electron과 arm64 패키지의 Node 실행에서 SQLite를 열었고 앱 묶음을 생성했다. 패키지 전체의 첫 설정·복원은 아직 확인하지 못했다.
- 제한: Node.js 24에서 실험 단계이므로 Electron·Node 업데이트 시 재검증한다. [Node.js SQLite 문서](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)

## 결정 008: 첫 실행·설정 시안과 목표 변경 저장

- 기록일: 2026-11-13 / 상태: 구현 / 근거: 사용자 요청과 `design/dashboard.html`.
- 결정: 대시보드 창에서 네 단계로 초기 설정하고, 설정에서 목표 중단·재생성과 한 잔 용량 변경을 제공한다. 가짜 macOS 창 버튼은 시안과 실제 UI에서 제거한다.
- 영향: 목표 재생성은 기존 목표 이력을 보존하며 오늘 총량의 차이를 저장한다. SQLite 스키마를 버전 2로 이전한다. 물 기록은 미구현이므로 현재 총량에는 조정만 포함한다.
