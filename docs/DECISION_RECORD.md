# 결정 기록

제품과 기술에 영향을 주는 결정을 이유와 함께 기록한다. 기존 항목을 지우지 않고 새 결정과 대체 관계를 추가한다. `확정`, `제안`, `실험`, `변경됨`을 구분하며, 제안은 확정된 기획을 덮어쓰지 않는다.

## 결정 001: 계정 없는 로컬 우선 MVP

- 기록일: 2026-11-13 / 상태: 확정 / 근거: [제품 개요](product.md), 사용자 대화.
- 결정: 회원가입·별도 서버 없이 Electron 앱과 SQLite를 사용한다. 기록과 설정은 이 Mac에 저장한다.
- 이유: 다운로드 후 가볍게 시작하고 오프라인에서도 사용할 수 있도록 한다.
- 영향: 기기 간 자동 동기화는 MVP에 없다. SQLite 연결과 백업·복원 정책은 구현·검증 전이다.

## 결정 002: 최초 설정과 목표 기록의 경계

- 기록일: 2026-11-13 / 상태: 확정 / 근거: [기능 명세](features.md).
- 결정: 사용자가 하루 목표량과 한 잔 용량을 직접 입력하며 최초 설정은 건너뛰지 않는다. 활성 목표가 없으면 물을 기록할 수 없다.
- 이유: 실제 사용자가 정한 기준으로 물을 기록하고, 목표가 없는 상태의 기록을 막는다.
- 영향: 목표 중단 후 재생성은 최초 설정과 다른 흐름이다. 기록과 설정은 저장 성공 후에만 화면에 반영한다.

## 결정 003: 오늘 현재 목표 기록 전체 취소

- 기록일: 2026-11-13 / 상태: 확정 / 근거: [취소 범위](features.md#취소-범위).
- 결정: 한국 시간 기준 오늘 현재 목표의 물 기록과 그 기록이 만든 성장만 취소한다. 목표, 이전 날짜, 다른 목표의 기록·성장과 기섭취량 조정은 유지한다.
- 이유: 목표 자체는 유지하면서 해당 목표로 오늘 기록한 물만 되돌리려는 사용자 의도다.
- 영향: 연관 데이터는 하나의 트랜잭션으로 처리하고 취소 후 총량이 음수가 되면 거절한다.

## 결정 004: 식물의 생기와 성장

- 기록일: 2026-11-13 / 상태: 확정된 방향 / 근거: [식물 반응과 성장](features.md#식물-반응과-성장).
- 결정: 물을 기록하면 생기가 회복되고, 목표 달성 및 초과 기록으로 쌓인 성장량에 따라 외형이 바뀐다. 앱 종료 중에도 아주 천천히 시든다.
- 이유: 물을 자주 마시는 습관과 장기적인 정원 가꾸기를 연결한다.
- 미정: 성장량·단계 기준, 시듦 속도와 일부 보상 정책은 실제 사용하며 정한다.

## 결정 005: 작은 정원과 Dock

- 기록일: 2026-11-13 / 상태: 기본 배치 확정, Dock 추적은 실험 / 근거: [정원과 창](features.md#정원과-창), 사용자 대화.
- 결정: 작은 화분을 오른쪽 아래에 두고, 왼쪽 위에 펼친 물뿌리개가 화분을 향하게 한다. 정원은 일반 앱 위·Dock 아래이며 우클릭·단축키·메뉴 막대로 숨김과 복귀를 제공한다.
- 이유: 작업을 덜 가리고 Dock 조작을 방해하지 않으며 물주기 연출 방향을 유지한다.
- 미정: Dock의 실제 확대·자동 숨김에 따라 움직이는 방식은 감지 안정성 등을 실험한 뒤 정한다. 실시간 추적은 현재 미구현이다.

## 결정 006: 물 마시는 동작 감지

- 기록일: 2026-11-13 / 상태: MVP 이후 실험 / 근거: [제품 개요](product.md#물-마시는-동작-감지-실험).
- 제안: MediaPipe와 카메라로 동작을 추정하고 사용자가 확인한 뒤 기록하도록 검토한다. 기본 꺼짐·로컬 처리와 수동 기록 유지 방향을 제안한다.
- 미정: 인식률, 확인 UI, 개인정보 처리 세부와 실제 도입 여부. 카메라는 음료가 물인지와 실제 섭취량을 확정하지 못한다.

## 결정 007: 최초 설정 SQLite는 Node 내장 모듈 사용

- 기록일: 2026-11-13 / 당시 상태: 구현, 패키지 앱 전체 검증 중 / 근거: Issue #1.
- 이후 확인: 로컬 ad-hoc arm64 패키지에서 첫 설정·재실행 복원을 확인했다. DMG 설치·배포 서명·공증은 별도 범위다. [최초 설정 결과](features/initial-setup-REPORT.md) 참고.
- 결정: Electron에 포함된 Node.js의 `node:sqlite`로 앱 데이터 폴더의 `hanzanhae.sqlite`를 사용한다. 스키마는 `user_version` 1부터 관리한다.
- 이유: 별도 네이티브 애드온 설치·재빌드 없이 로컬 트랜잭션과 파일 저장을 사용할 수 있다.
- 확인: 개발 Electron과 arm64 패키지의 Node 실행에서 SQLite를 열었고 앱 묶음을 생성했다. 패키지 전체의 첫 설정·복원은 아직 확인하지 못했다.
- 제한: Node.js 24에서 실험 단계이므로 Electron·Node 업데이트 시 재검증한다. [Node.js SQLite 문서](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)

## 결정 008: 첫 실행·설정 시안과 목표 변경 저장

- 기록일: 2026-11-13 / 상태: 구현 / 근거: 사용자 요청과 `design/dashboard.html`.
- 결정: 대시보드 창에서 네 단계로 초기 설정하고, 설정에서 목표 중단·재생성과 한 잔 용량 변경을 제공한다. 가짜 macOS 창 버튼은 시안과 실제 UI에서 제거한다.
- 영향: 목표 재생성은 기존 목표 이력을 보존하며 오늘 총량의 차이를 저장한다. SQLite 스키마를 버전 2로 이전한다. 당시 물 기록은 미구현이어서 총량에는 조정만 포함했다. 이후 물 기록 연결은 결정 009를 따른다.

## 결정 009: 물 기록과 기존 총량 조정의 합산

- 기록일: 2026-11-13 / 상태: 구현 / 근거: [물 기록 계획](features/water-record-PLAN.md), 기존 목표 변경·총량 규칙.
- 결정: 현재 목표와 저장된 한 잔 용량으로 물 기록을 저장한다. 한국 날짜별 총량은 이전 목표를 포함한 유효 물 기록과 조정의 합이며, 잔 수는 물 기록만 센다.
- 영향: 스키마 버전 3으로 이전하고 요청 ID를 기록과 함께 저장한다. 당시 취소·생기·성장 보상은 미구현이었다. 취소는 결정 010, 이후 생기·성장은 결정 011을 따른다.

## 결정 010: 취소 대상 확인과 보존

- 기록일: 2026-11-13 / 상태: 구현 / 근거: [취소 계획](features/water-cancel-PLAN.md), 결정 003.
- 결정: 최근 취소는 현재 목표의 오늘 최신 기록 하나, 전체 취소는 사용자가 확인한 현재 목표의 오늘 유효 기록만 대상으로 한다. 확인 이후 대상·목표·날짜가 바뀌거나 총량이 음수가 되면 거절한다.
- 영향: 스키마 버전 4에서 취소 시각과 요청 결과를 함께 저장해 중복을 막는다. 목표·다른 기록·조정은 보존한다. 이후 결정 011에서 연관 성장도 같은 트랜잭션의 취소에 연결했다.

## 결정 011: 생기와 성장의 임시 구현 기준

- 기록일: 2026-11-14 / 상태: 실험 / 근거: [생기와 성장 계획](features/plant-growth-PLAN.md).
- 기록: 목표 첫 달성 1,000점과 초과량 비례 성장, 단계 0·3,000·7,000·14,000점. 물 기록당 생기 +15%p, 실행 중 시간당 -2%p, 종료 중 -0.25%p, 범위 20~100%. 초기값 80%.
- 기존 데이터는 성장으로 소급하지 않고, 목표 변경·조정만으로 보상하지 않는다. 기록 취소는 그 기록의 성장만 되돌리며 생기 회복은 유지한다. 수치는 실제 사용하며 조정한다.

## 결정 012: 디자인 시안 로컬 관리

- 기록일: 2026-11-14 / 상태: 확정 / 근거: 사용자 요청.
- `design/`은 Git 추적에서 제외하고 로컬에서 관리한다. 앱 실행 에셋은 별도로 저장소에 둔다. 새 클론에는 시안이 없으므로 필요하면 사용자에게 요청한다.

## 결정 013: 대시보드 통계의 날짜와 연속 달성

- 기록일: 2026-11-14 / 상태: 첫 구현 기준 / 근거: [물 섭취 통계 계획](features/water-statistics-PLAN.md).
- 일별 마지막 활성 목표를 시작·중단 이력에서 복원하고, 물 기록 취소와 총량 조정을 반영한다. 목표 중단 당일은 마지막 목표를 사용하고 이후 새 목표가 없는 날은 목표 없음이다.
- 7일 평균과 달성 횟수는 목표가 있었던 날을 분모로 한다. 과거 목표 없는 날과 미달성은 연속 달성을 끊으며, 오늘 미달성은 아직 진행 중으로 보고 어제부터 계산한다.
- 최다량 동률은 가장 최근 날짜를 선택하고 기록 총량이 0인 경우 최다일을 표시하지 않는다.

## 결정 014: 정원 위치와 창 설정

- 기록일: 2026-11-14 / 상태: 구현·기본 사용자 확인, 다중 모니터와 Dock 반응 미확인 / 근거: [정원 위치 계획](features/garden-position-PLAN.md).
- 화분을 자유롭게 끌어 옮기고 좌표·프리셋·항상 위 여부를 로컬에 저장한다. 직접 이동은 `custom`, 설정 프리셋은 `dock`과 `floor`로 구분한다.
- 화면 밖 위치는 연결된 화면 안으로 복구한다. Dock 위는 작업 영역 하단, 화면 바닥은 화면 하단이며 Dock 확대·숨김 추적은 별도 실험이다.

## 제안 015: 식물 상태를 활용한 시스템 알림

- 기록일: 2026-11-14 / 당시 상태: 제안·미구현. 이후 결정 016에서 첫 구현 기준으로 구체화했다 / 근거: 사용자 요청, [제품 개요](product.md#식물이-보내는-물-마시기-알림).
- 물을 오래 기록하지 않으면 식물이 말을 거는 macOS 알림을 검토한다. 마지막 기록과 식물 생기를 조건으로 쓰는 방식, 앱 실행 중 알림과 사용자 설정은 제안이다.
- 알림 조건·기본 간격·알림 시간대·목표 달성 후 동작·앱 종료 중 동작은 미정이다. 서명된 패키지에서 알림 허용과 표시·클릭을 별도로 확인해야 한다.

## 결정 016: 알림 첫 구현 기준

- 기록일: 2026-11-14 / 상태: 임시 구현, macOS 표시 검증 필요 / 근거: [알림 PLAN](features/plant-reminders-PLAN.md). 제안 015를 구체화한다.
- 알림은 기본 꺼짐이며 1~8시간 간격과 한국 시간대를 설정한다. 최초 기준은 2시간·09:00~21:00이다.
- 앱 실행 중 활성 목표가 미달이고 마지막 기록·목표 시작·마지막 표시 이후 간격을 충족하면 요청한다. 식물 생기에 따라 문구를 고르고 알림 클릭만으로 물을 기록하지 않는다.
- macOS의 알림 표시와 클릭은 사용자가 확인했다. 간격 경과 후 자동 알림은 별도로 확인한다. 앱이 완전히 종료된 상태의 알림은 제외하며 수치와 문구는 사용하면서 조정한다.
